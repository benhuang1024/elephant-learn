PHP 架构师的对照

Laravel 的管线是 Middleware → Controller → (FormRequest 校验) → Service；Nest 把校验抽成 Pipe、把认证抽成 Guard、把横切计时抽成 Interceptor、把异常映射抽成 Filter。

顺序很重要：Guard 在 Pipe 之前——未认证的请求根本不会走到校验；Filter 在最外圈——任何一站抛错都被它接住转成 problem+json。

四个值得记住的分支

  • 无认证 → 401，Accept 决定有没有 body 与 WWW-Authenticate。
  • customer 删商品 → 403；admin → 204 空 body。
  • 校验失败 → 400 + errors: {"items[0].quantity": …}。
  • 库存不足 / 乐观锁冲突 → 409 + problem+json，带 sku/requested/available。

为什么并发会 409

两个请求都读到 version=0；第一个 commit 后 version=1；第二个的 UPDATE … WHERE id=? AND version=0 影响 0 行 → 抛乐观锁冲突。

语义与 Hibernate 的 @Version 一致，只是这里手写 WHERE。打开「并发两单」看第二个请求在 Repository 站变红。
