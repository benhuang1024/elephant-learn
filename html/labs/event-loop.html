PHP 架构师的对照

      
PHP-FPM 是 share-nothing：每个请求 bootstrap 一次框架，请求结束释放全部内存。所以「顺序」在一个请求内就是一条直线，你从来不需要考虑队列。

      
用过 Octane / Swoole / RoadRunner 的话你已经有半个直觉：协程让出点 ≈ await，Swoole\Coroutine::defer ≈ 微任务。差别是 Node 把这件事变成了语言默认，而不是可选扩展。

    

    

      
三条最容易记错的规则

      
    
        
  • setTimeout(fn, 0) 不是立刻：它排在所有微任务后面。
    • 
        
  • 微任务阶段是「清空为止」：微任务里再生的微任务仍在本轮执行，早于下一个宏任务。
    • 
        
  • await 不释放线程，只释放「这段代码往后」的执行权；await null 也会让出。
    • 
      

    

    

      
为什么这章值一整天

      
单线程保证的是「一段同步代码不会被打断」，不保证「你的函数从头到尾原子」。看「await 让出点竞态」片段：全程一个线程，余额仍被扣成 -20。

      
修法不是加锁，而是：await 之后再检查 + 把唯一真相放数据库（事务 + 乐观锁）。进程内变量做不了分布式一致性。
