# 06 会议、汇报与书面沟通

> 乙方的专业感，很大程度上体现在**会议开得好不好、周报写得清不清、邮件发得准不准**。
> 这些是每天都在发生的"小事"，却在持续塑造甲方对你的印象。

---

## 1. 会议

### 1.1 会议前：80% 的效果在会前决定

**会前检查清单**：
- [ ] 这个会必须开吗？能不能用邮件 / 电话 / 文档评论解决？
- [ ] 会议目标是什么？（信息同步 / 讨论 / 决策——三选一，最多二）
- [ ] 必须参加的人是谁？决策人在不在？
- [ ] 议程发出去了吗？（至少提前 1 天）
- [ ] 需要对方提前看的材料发出去了吗？
- [ ] 有分歧的议题，会前和关键人私下沟通过了吗？（会前会）
- [ ] 会议室、投屏、线上链接准备好了吗？

**会议通知模板**：

```
主题：【XX 项目】需求评审会 - 11/5 周二 14:00-15:00

会议目标：确认审批模块的需求范围，形成评审结论

议程：
1. 14:00-14:10 审批模块需求概述（乙方 张三）
2. 14:10-14:40 逐条评审，重点讨论第 3、5、7 条（全体）
3. 14:40-14:55 待定事项讨论及决策（王经理）
4. 14:55-15:00 总结及下一步

需要提前阅读：附件《审批模块需求说明 v1.2》，重点关注第 3 章
参会人：甲方 王经理、李工、赵科长；乙方 张三、小李
地点：甲方 3 楼会议室 / 腾讯会议 xxx-xxx-xxx
```

### 1.2 会议中：控场

**开场（2 分钟）**：
> "感谢各位参加。今天会议主要目标是确认审批模块的需求范围。议程有 4 项，预计一小时。我们争取 3 点准时结束。"

**控场技巧**：

| 情况 | 应对话术 |
|---|---|
| 跑题 | "这个问题很重要，我先记到'待议事项'里，会后单独讨论。我们先回到……" |
| 有人一直说 | "谢谢 X 总的意见，我们也听听业务部门的想法？赵科长您觉得呢？" |
| 有人不说话 | "李工，从技术角度您觉得这个方案有什么风险吗？"（点名提问） |
| 争论不休 | "两种观点都有道理，我们把分歧点记下来：A 关注……，B 关注……。这个需要王经理来决定，或者我们会后补充数据再议？" |
| 时间不够 | "时间关系，剩下两项我们会后通过邮件确认，大家看行吗？" |
| 领导临时插话改方向 | "好的，李总的意见我记下了。这个方向调整涉及到……，我们会后评估影响再向您汇报？" |

**每个议题结束时**：
> "这一项我总结一下：结论是……；待办是……，由 X 负责，Y 日前完成。大家有没有异议？"

**结束（5 分钟）**：
> "今天我们确认了 X 项，有 Y 项待定。待办事项是：1……2……3……。会议纪要我今天下班前发给大家。"

### 1.3 会议后：纪要是乙方的保险

**24 小时内（最好当天）发出会议纪要**，模板见 [templates/会议纪要.md](templates/会议纪要.md)。

**纪要要点**：
- **只写结论和待办，不写过程**（谁说了什么不重要，定了什么才重要）
- 每个待办有：**事项、负责人、截止时间**
- 结尾加一句："如有遗漏或不同意见，请在 X 日前回复，否则视为确认。"

**纪要的"小心机"**：
- 对乙方有利的结论，写得明确具体
- 甲方承诺配合的事项，写清楚时间和责任人
- 甲方领导提出的变更，写明"需评估影响后另行确认"
- 风险提示写进去："乙方提示：如 X 日前数据未到位，上线可能顺延"

### 1.4 几类关键会议的要点

| 会议 | 目标 | 乙方要点 |
|---|---|---|
| **启动会** | 统一目标、明确分工、建立机制 | 请甲方领导出席讲话；明确甲方配合事项和责任人；确定沟通机制（周会、周报、升级路径） |
| **需求评审** | 确认需求范围 | 原型演示；逐条确认；明确 Out of Scope；签字 |
| **周例会** | 同步进度、解决问题 | 15 分钟进度 + 30 分钟问题；问题清单逐条过 |
| **方案评审** | 确定技术/业务方案 | 会前会；方案对比表；给推荐 |
| **上线评审** | 决定能否上线 | 测试报告、回滚方案、应急预案；让甲方签字确认上线 |
| **验收会** | 完成验收 | 演示亮点、数据说话、验收材料齐全、提前准备好签字页 |
| **复盘会** | 总结经验 | 对事不对人；聚焦改进措施 |

## 2. 汇报

### 2.1 向甲方对接人汇报（日常）

**频率**：
- 日报（关键时期，如上线前一周）：3-5 行即可
- 周报：每周固定时间（如周五下午）
- 重大事项：随时

**周报结构**（模板见 [templates/项目周报.md](templates/项目周报.md)）：

```
1. 总体状态：🟢 正常 / 🟡 有风险 / 🔴 严重延误
   一句话总结：本周完成需求评审，开发进度 45%，略超计划。

2. 本周完成（对照计划）
3. 下周计划
4. 风险与问题（需要甲方关注/支持的事项，标红）
5. 里程碑进度（甘特图或表格）
6. 附：本周变更清单
```

**周报的原则**：
- **第一句话就是结论**——甲方很可能只看第一句
- **红黄绿灯**——一眼看出状态
- **需要甲方做的事，单独列出、加粗**——不要埋在正文里
- **风险要写**——哪怕甲方不看，以后出事你能说"周报里提过"
- **数据说话**——"完成 15/20 个功能点"而不是"大部分已完成"

### 2.2 向甲方领导汇报

**领导的特点**：时间少、看大局、关注结果和风险、不关心技术细节。

**汇报结构：结论 → 支撑 → 请求**

```
1. 一句话结论（项目整体怎么样）
2. 三个关键数字（进度、质量、成本 / 业务价值）
3. 一个需要领导关注的风险或决策
4. 下一阶段重点
```

**PPT 原则**：
- 一页一个观点，标题就是观点（"系统上线后审批效率提升 6 倍"，而不是"上线效果"）
- 正文不超过 5 行
- 多用图表，少用文字
- 准备备用页（详细数据）放在附录，被问到时再翻

**汇报时的技巧**：
- 开场先感谢领导的支持和对接人的配合（给对接人面子）
- 准备好被打断——领导经常听两句就开始问问题
- 领导问到不知道的："这个数据我确认一下，会后马上发给您"——**不要现场编**
- 结束时明确请领导做什么："今天想请李总定一下二期范围"

### 2.3 向乙方内部领导汇报

**和向甲方汇报的区别**：可以更坦诚地讲问题和风险，要讲清楚**需要领导帮什么忙**。

```
1. 项目状态（红黄绿）
2. 财务状况：合同额、已回款、待回款、成本消耗
3. 主要风险及需要支持的事项
4. 客户关系：甲方满意度、关键人态度变化
5. 商机：有没有后续合作机会
```

**向上汇报的禁忌**：
- 只报喜不报忧——领导最怕"惊喜"
- 只报忧不带方案——"领导，出问题了，怎么办？"
- 不分轻重——所有事都找领导

## 3. 书面沟通

### 3.1 邮件

**标题**：要能让人不打开就知道是什么事、要不要处理
- ❌ "关于项目的一些问题"
- ✅ "【XX 项目】【需确认】审批流程第 3 条修改方案 - 请 11/5 前回复"

**标题标签**：
- 【通知】：只需知晓
- 【需确认】/【需审批】：需要对方行动
- 【紧急】：慎用，用多了就不紧急了
- 【风险】：提示风险

**正文结构**：
```
王经理您好，

【一句话说明来意】
关于审批流程第 3 条的修改，需要您确认一下方案，11/5 前回复即可。

【背景（简短）】
上周评审会上，赵科长提出会签需要支持"或签"模式。

【方案 / 内容】
我们评估了两个方案：
1. 方案 A：……（2 人天，不影响工期）
2. 方案 B：……（5 人天，工期顺延 2 天）
建议方案 A。

【需要对方做什么】
请您确认采用哪个方案。如 11/5 前未收到回复，我们将按方案 A 实施。

张三
XX 公司 | XX 项目经理 | 138xxxx
```

**收件人 / 抄送**：
- 收件人 = 需要行动的人
- 抄送 = 需要知晓的人
- **抄送领导要慎重**：抄送对方领导可能被理解为"告状"；抄送自己领导要考虑是否必要
- 重要邮件不要密送（BCC），被发现会严重损害信任

### 3.2 即时消息（微信 / 企业微信 / 钉钉）

**原则**：
- **不要只发"在吗"**——直接说事
- 一条消息说完整，不要拆成 10 条
- 重要事项：消息里说，**再补一封邮件留痕**
- 群消息：@具体人，否则没人觉得是自己的事
- 工作时间外：非紧急不发；紧急的先发消息再打电话
- 语音消息：尽量不发给甲方（对方可能在开会，不方便听）

**示例**：
- ❌ "王经理在吗"
- ✅ "王经理，测试服务器的账号今天能给到吗？我们下午想开始部署。如果有困难告诉我，我来跟 IT 那边对接。"

### 3.3 正式函件

**什么时候发正式函件**：
- 重大变更确认
- 进度延误的正式告知（尤其是甲方原因导致的）
- 催款
- 合同争议

**注意**：正式函件意味着"走程序"，会让关系变得正式甚至紧张。发之前：
1. 先口头沟通过
2. 告知对方"按公司流程，需要发一份正式函件，走个程序"
3. 措辞客观，不带情绪

## 4. 电话与当面沟通

### 4.1 什么时候必须打电话 / 当面

- 坏消息（延期、事故、人员变动）
- 有争议、容易误解的事
- 紧急的事
- 需要建立关系的时候
- 文字来回 3 轮还没说清的事

**原则**：**坏消息当面说，好消息书面说**（书面说好消息，对方可以转发给领导；当面说坏消息，可以看到对方反应、及时安抚）。

### 4.2 电话的结构

1. 确认对方是否方便："王经理，现在方便说两分钟吗？"
2. 说明来意："想跟您同步一下测试服务器的事。"
3. 说事（结论先行）
4. 确认结论："那我们就定……，对吧？"
5. 告知后续："我待会儿把刚才说的发个消息给您确认一下。"

## 5. 本章练习

1. 拿你最近一份周报，用本章的结构改写，对比效果。
2. 拿你最近 5 封邮件的标题，按本章原则改写。
3. 下一次会议，刻意练习"每个议题结束时总结结论和待办"。
4. 下一次会议后，2 小时内发出会议纪要，并在结尾加上"如有异议请在 X 日前回复"。
5. 准备一份 3 页以内的领导汇报 PPT，每页标题都是一个结论。
