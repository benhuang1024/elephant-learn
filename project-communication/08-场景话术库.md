# 08 场景话术库

> 按场景速查。**不要死记硬背**，理解背后的原理后用自己的话说出来。
> 建议：把你最常用的 20 条抄到手机备忘录里，开会前看一眼。
> 每条话术后的【】标注了它用到的技巧，可回到对应章节复习。

## A. 日常沟通与关系建立（1-12）

| # | 场景 | 推荐说法 |
|---|---|---|
| 1 | 第一次见对接人 | "王经理，以后项目上的事您直接找我就行，我这边有任何情况也会第一时间跟您同步。您平时习惯电话还是微信？"【建立沟通机制】 |
| 2 | 了解对方的期望 | "您觉得这个项目做到什么程度，算是成功了？"【探询真实目标】 |
| 3 | 了解对方领导 | "李总那边对这个项目最关注的是哪方面？"【识别决策人诉求】 |
| 4 | 了解对方的顾虑 | "之前做类似项目，您遇到过什么坑吗？我们这次尽量避开。"【挖掘隐性风险】 |
| 5 | 承诺小事 | "我下午 3 点前把材料发您。"（然后 2:50 发）【可靠性】 |
| 6 | 不知道答案时 | "这个我需要确认一下，今天下班前给您准确答复。"【不乱说】 |
| 7 | 表达感谢 | "多亏您帮忙协调，测试环境今天就到位了，省了我们好几天。"【具体化感谢】 |
| 8 | 给对接人面子 | "这次能按时完成，王经理在里面协调了很多事。"（当着他领导说）【给功劳】 |
| 9 | 主动同步 | "王经理，没什么大事，就是跟您同步一下本周进展，一切正常。"【无事也报平安】 |
| 10 | 询问反馈 | "最近用下来，业务部门那边有什么反馈吗？好的坏的都想听听。"【主动收集】 |
| 11 | 节日问候 | "王经理，中秋快乐！这一年项目上多亏您支持。"（不谈工作）【关系维护】 |
| 12 | 对方升职 / 调岗 | "恭喜王经理！以后有什么需要我们支持的，随时说。"【长期关系】 |

## B. 需求沟通（13-28）

| # | 场景 | 推荐说法 |
|---|---|---|
| 13 | 需求不清 | "您说的'灵活'，能举个具体例子吗？比如什么情况下需要调整？"【具体化】 |
| 14 | 追问目的 | "这个功能做完之后，主要是给谁用、解决什么问题？"【5W2H】 |
| 15 | 甲方说"你们看着办" | "好的，我们出两个方案给您选，您定了我们再做，免得返工。"【给选项】 |
| 16 | 甲方说"跟 XX 系统一样就行" | "XX 系统里的哪几个功能是您最看重的？我们重点参考那几块。"【聚焦】 |
| 17 | 确认理解 | "我复述一下我的理解，您看对不对……"【复述确认】 |
| 18 | 推动签字 | "签个字主要是为了咱们理解一致，后面您向领导汇报也有依据。有调整随时走变更。"【利益翻译】 |
| 19 | 甲方不签字 | "那我发邮件给您，三个工作日内没有修改意见，我们就按这个版本开始了？"【默认确认】 |
| 20 | 新需求进来 | "这个想法很好，我先登记下来，评估一下工作量和对工期的影响，明天给您答复。"【不当场答应】 |
| 21 | "这个很简单" | "看起来确实不复杂，我们评估一下会不会影响其他功能，评估完马上告诉您。"【不否定但不答应】 |
| 22 | "这不是本来就该有的吗" | "从业务上看确实需要。需求文档里当时没覆盖到，咱们一起看看怎么补上。"【不推责、走流程】 |
| 23 | 拒绝新需求 | "可以做。不过要加的话，有两个选择：上线推迟 X 天，或者把 Y 功能挪到二期。您看哪个合适？"【用代价代替拒绝】 |
| 24 | 需求冲突 | "业务部和 IT 部的考虑都有道理，这个需要贵司内部定个方向，我们两种都能实现。"【不当裁判】 |
| 25 | 领导临时提需求 | "李总的想法很好，我们会后评估一下实现方式和影响，再向您汇报。"【不当场承诺】 |
| 26 | 开发直接被甲方找 | （开发说）"这个我记下来了，跟项目经理确认后给您回复。"【统一入口】 |
| 27 | 统计变更 | "这个月咱们一共调整了 23 处，其中 18 处小改动已经免费做了，剩下 5 处想跟您商量下。"【让积累可见】 |
| 28 | 不建议做某需求 | "从专业角度，我们不太建议这么做，原因是……。如果您还是决定要做，我们会按您的要求来，但想把风险记录一下。"【专业建议+留痕】 |

## C. 进度与汇报（29-42）

| # | 场景 | 推荐说法 |
|---|---|---|
| 29 | 汇报进度 | "整体正常，完成 15/20 个功能点。有一个风险需要您关注：……"【结论先行+数据】 |
| 30 | 铺垫风险（初期） | "跟您同步一个情况，XX 进度有点慢，我们在盯，目前还不影响整体。"【预先铺垫】 |
| 31 | 铺垫风险（加剧） | "XX 还没进展，如果周五前还解决不了，上线可能会受影响。我们在准备备选方案。"【预先铺垫】 |
| 32 | 告知延期 | "结论先说：上线建议从 15 号调到 22 号。原因两点……我们有两个方案……"【结论先行+选项】 |
| 33 | 承认自己的问题 | "这个问题我们应该更早发现、更早跟您说，这是我们的问题。现在想跟您商量怎么把影响降到最小。"【担责】 |
| 34 | 延期中有甲方原因 | "数据是上周三到位的，比计划晚了 5 天，加上我们这边性能优化需要 3 天，所以……"【客观陈述不指责】 |
| 35 | 给对接人弹药 | "您向李总汇报时需要什么材料？我们准备一页纸的说明。"【降低对方成本】 |
| 36 | 被问到不知道的 | "这个数据我确认一下，会后马上发您。"【不现场编】 |
| 37 | 汇报开场 | "感谢李总的支持，也感谢王经理这段时间的协调。我用 5 分钟汇报一下……"【给面子+控时】 |
| 38 | 请领导决策 | "今天想请李总定一件事：二期要不要加移动端。"【明确请求】 |
| 39 | 承诺时间 | "在接口文档周三到位的前提下，我们有把握 20 号前完成。"【有条件的承诺】 |
| 40 | 被追问"到底什么时候好" | "我给您一个准确的时间：今天下午 5 点前，我会告诉您确切的完成时间。"【给确定性】 |
| 41 | 被质疑能力 | "您的担心我理解。我们之前在 XX 做过类似项目，我可以把案例材料发您看看。"【第三方背书】 |
| 42 | 阶段性成果后 | "一期上线一个月，审批时长从 3 天降到 0.5 天。这个数据您看要不要用在给领导的汇报里？"【给政绩】 |

## E. 突发事件（59-74）

| # | 场景 | 推荐说法 |

| 69 | 人员离职 | "跟您同步一个团队调整：小李下周离开项目，老张接手，两人这两周一起交接，对进度没有影响。"【已安排好】 |
| 70 | 新领导推翻方案 | "李总的意见很重要。能具体说一下您期望的效果吗？我们评估后给您两个方案。"【探询+不当场争】 |
| 71 | 对接人换人 | "王经理，您调岗前能不能帮我们跟新同事做个交接？资料我们都准备好了。"【平稳过渡】 |

| 74 | 主动补偿 | "为了表达歉意，本月我们安排一个工程师驻场，确保系统稳定。"【补偿】 |

## 高危话术：千万别说

| 别说 | 为什么 | 换成 |
|---|---|---|
| "这不是我们的问题" | 推卸，激化矛盾 | "我们先一起解决，原因后面详细分析" |
| "肯定没问题 / 保证" | 一旦失败，信用破产 | "在 X 条件下，我们有把握……" |
| "你们不懂技术" | 侮辱对方 | "这块技术上稍微复杂，我简单解释一下" |
| "合同里没写" | 冷冰冰，伤关系 | "需求文档里当时没覆盖到，咱们一起看看怎么补上" |
| "我们公司规定……" | 自我导向，甲方不关心 | "为了保证质量 / 安全，我们建议……" |
| "这个很简单" | 降低自己的价值，也给自己挖坑 | "我们评估一下" |
| "马上就好" | 往往做不到 | "预计 X 点前，我 Y 点给您更新" |
| "我们领导不批" | 把内部问题甩给甲方 | "这个我们内部再争取一下" |
| "上次你们也是这样" | 翻旧账 | 聚焦当下问题 |
| "随便 / 都行" | 不专业 | "我们建议 X，原因是……" |
| "我早就说过了" | 事后诸葛亮，让对方难堪 | "我们一起看看下一步怎么办" |
| "你们那个谁谁谁……" | 背后说人，迟早传到对方耳朵 | 对事不对人 |
