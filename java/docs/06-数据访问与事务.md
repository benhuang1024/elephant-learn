# 06 数据访问与事务

## 1. 技术选型地图

| 你在 PHP 里用 | Java 里的对应 | 定位 |
|---|---|---|
| PDO | JDBC | 底层驱动接口 |
| 原生 SQL + PDO 封装 | `JdbcClient`（Spring） | 手写 SQL，轻量 |
| Doctrine DBAL / Query Builder | **jOOQ**（类型安全 SQL DSL） | SQL 优先、强类型 |
| 半 ORM，SQL 写在 XML/注解 | **MyBatis / MyBatis-Plus** | **国内最主流** 之一 |
| Doctrine ORM（Data Mapper + Unit of Work） | **JPA / Hibernate** | 全功能 ORM，Spring 官方首选 |
| Eloquent（Active Record） | —（Java 主流没有 AR 风格） | |
| Laravel Migrations | **Flyway** / Liquibase | 数据库迁移 |
| 连接池（php-fpm 下基本没有） | **HikariCP**（Boot 默认） | |

> 如果你熟悉 Doctrine，JPA 几乎可以无缝上手：Entity、EntityManager、Unit of Work、Repository、DQL ↔ JPQL 都是一一对应的。如果你只用过 Eloquent，请重点阅读第 3 节“持久化上下文”。

本章以 **JPA + Spring Data JPA** 为主线，因为 Spring 生态默认用它；最后对比 MyBatis 和 JdbcClient 的使用场景。

## 2. 迁移：Flyway

```
src/main/resources/db/migration/
├── V1__create_product.sql
├── V2__create_order.sql
└── V3__add_product_version.sql
```

```sql
-- V1__create_product.sql
CREATE TABLE product (
    id          BIGSERIAL PRIMARY KEY,
    sku         VARCHAR(32)    NOT NULL UNIQUE,
    name        VARCHAR(100)   NOT NULL,
    price       NUMERIC(12, 2) NOT NULL,
    stock       INT            NOT NULL,
    version     BIGINT         NOT NULL DEFAULT 0,
    created_at  TIMESTAMPTZ    NOT NULL DEFAULT now()
);
```

| Laravel | Flyway |
|---|---|
| `php artisan migrate` | 应用启动时自动执行 |
| `migrations` 表 | `flyway_schema_history` 表 |
| PHP 写 schema | 直接写 SQL（更透明，DBA 友好） |
| `migrate:rollback` | 社区版没有 down —— 业界做法是“只向前”，回滚也写成一个新的迁移 |

Spring Boot 4 中需要引入 `spring-boot-starter-flyway`（以及数据库对应的 `flyway-database-postgresql`）。
配合 `spring.jpa.hibernate.ddl-auto=validate`：Hibernate 启动时校验实体与表结构一致，**绝不要在生产用 `update`**。

## 3. JPA 实体与持久化上下文

```java
@Entity
@Table(name = "product")
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true, length = 32)
    private String sku;

    private String name;
    private BigDecimal price;
    private int stock;

    @Version                      // 乐观锁版本号
    private long version;

    protected Product() {         // JPA 要求无参构造器（可以是 protected）
    }

    public Product(String sku, String name, BigDecimal price, int stock) {
        this.sku = sku;
        this.name = name;
        this.price = price;
        this.stock = stock;
    }

    /** 领域行为放在实体里，而不是在 Service 里 setStock(getStock() - n) */
    public void deductStock(int quantity) {
        if (quantity > stock) {
            throw new BusinessException("INSUFFICIENT_STOCK",
                    "库存不足 sku=%s 需要=%d 剩余=%d".formatted(sku, quantity, stock));
        }
        this.stock -= quantity;
    }

    // getters ...
}
```

> 实体 **不要** 用 record：JPA 需要可变对象、无参构造器和代理子类。record 用于 DTO 和投影。

### 最重要的概念：持久化上下文（≈ Doctrine 的 Unit of Work）

```java
@Transactional
public void rename(Long id, String newName) {
    Product p = productRepository.findById(id).orElseThrow();
    p.rename(newName);
    // 没有调用 save()！
}   // 事务提交时，Hibernate 发现 p 被修改（脏检查），自动执行 UPDATE
```

Eloquent 用户最不适应的地方：

| Eloquent | JPA |
|---|---|
| `$p->name = 'x'; $p->save();` 显式保存 | 事务内修改托管实体，提交时 **自动 flush** |
| 每次 `find` 都查库 | 同一事务内同一 id 只查一次（一级缓存），返回 **同一个对象实例** |
| 模型随时可以访问关系（懒加载随时可用） | 懒加载只能在 **事务/Session 打开时** 触发，否则 `LazyInitializationException` |
| 没有“托管/游离”状态 | 实体有 new / managed / detached / removed 四种状态 |

## 4. Spring Data Repository：只写接口

```java
public interface ProductRepository extends JpaRepository<Product, Long> {

    // 方法名派生查询：自动生成 SELECT ... WHERE sku = ?
    Optional<Product> findBySku(String sku);

    // ≈ Product::where('name', 'like', "%$kw%")->where('stock', '>', 0)->paginate()
    Page<Product> findByNameContainingIgnoreCaseAndStockGreaterThan(String keyword, int stock, Pageable pageable);

    boolean existsBySku(String sku);

    // 复杂查询写 JPQL（面向实体，不是表）
    @Query("select p from Product p where p.price between :min and :max order by p.price")
    List<Product> findInPriceRange(BigDecimal min, BigDecimal max);

    // 原生 SQL
    @Query(value = "select * from product where stock < :threshold", nativeQuery = true)
    List<Product> findLowStock(int threshold);

    // 批量更新：直接执行 UPDATE，不经过实体
    @Modifying
    @Query("update Product p set p.stock = p.stock - :qty where p.id = :id and p.stock >= :qty")
    int deductStockAtomically(Long id, int qty);

    // 投影：只查需要的列，直接映射成 record
    @Query("select new com.acme.shop.product.ProductSummary(p.id, p.name, p.price) from Product p")
    List<ProductSummary> findSummaries();
}
```

`JpaRepository` 已提供 `save`、`findById`、`findAll(Pageable)`、`deleteById`、`count` 等方法。Spring 在启动时为接口生成实现类。

## 5. 关联与 N+1

```java
@Entity
@Table(name = "orders")
public class Order {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();

    @Enumerated(EnumType.STRING)     // 存字符串而不是序号，否则调整枚举顺序会破坏数据
    private OrderStatus status;

    public void addItem(Product product, int qty) {
        items.add(new OrderItem(this, product, qty, product.getPrice()));
    }
}

@Entity
public class OrderItem {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne(fetch = FetchType.LAZY)       // ⚠️ @ManyToOne 默认是 EAGER，务必显式改成 LAZY
    private Order order;

    @ManyToOne(fetch = FetchType.LAZY)
    private Product product;

    private int quantity;
    private BigDecimal unitPrice;
}
```

N+1 和 Eloquent 一样会发生，解决方式对应：

| Eloquent | JPA |
|---|---|
| `Order::with('items')->get()` | `@EntityGraph(attributePaths = "items")` 或 `join fetch` |
| `Model::preventLazyLoading()` | `spring.jpa.open-in-view=false` + 测试中统计 SQL 数量 |

```java
@EntityGraph(attributePaths = {"items", "items.product"})
Optional<Order> findWithItemsById(Long id);

@Query("select distinct o from Order o join fetch o.items where o.status = :status")
List<Order> findWithItemsByStatus(OrderStatus status);
```

**务必设置 `spring.jpa.open-in-view: false`**。默认开启的 OSIV 会让数据库连接持续占用到视图渲染/JSON 序列化结束，把懒加载问题藏起来、在高并发下耗尽连接池。关闭后，在 Service 层把需要的数据一次加载好，转换成 DTO 再返回。

开发时打开 SQL 日志：

```yaml
logging:
  level:
    org.hibernate.SQL: debug
    org.hibernate.orm.jdbc.bind: trace   # 打印绑定参数
```

## 6. 事务：`@Transactional`

```php
// Laravel
DB::transaction(function () use ($cmd) {
    $product = Product::lockForUpdate()->findOrFail($cmd->productId);
    $product->decrement('stock', $cmd->qty);
    Order::create([...]);
});
```

```java
@Service
public class OrderService {

    private final ProductRepository products;
    private final OrderRepository orders;

    public OrderService(ProductRepository products, OrderRepository orders) {
        this.products = products;
        this.orders = orders;
    }

    @Transactional
    public Long place(PlaceOrderRequest req) {
        var order = new Order();
        for (var line : req.items()) {
            Product p = products.findById(line.productId())
                    .orElseThrow(() -> new NotFoundException("商品不存在: " + line.productId()));
            p.deductStock(line.quantity());        // 抛 RuntimeException → 整个事务回滚
            order.addItem(p, line.quantity());
        }
        return orders.save(order).getId();
    }   // 正常返回 → 提交：flush 所有变更（UPDATE product / INSERT orders / INSERT order_item）

    @Transactional(readOnly = true)               // 只读事务：跳过脏检查，可路由到从库
    public OrderResponse get(Long id) {
        return orders.findWithItemsById(id)
                .map(OrderResponse::from)          // 在事务内完成 DTO 转换，懒加载安全
                .orElseThrow(() -> new NotFoundException("订单不存在: " + id));
    }
}
```

### 必须记住的事务规则

| 规则 | 说明 |
|---|---|
| 默认只回滚 `RuntimeException` 和 `Error` | 受检异常 **不回滚**。需要时写 `@Transactional(rollbackFor = Exception.class)` |
| 只对 **public 方法、从外部调用** 生效 | 同一个类里 `this.place()` 调用 **不经过代理，事务不生效**（原理见第 07 章） |
| 异常被 catch 吞掉就不会回滚 | 内层抛异常标记了 rollback-only，外层吞掉后提交会抛 `UnexpectedRollbackException` |
| 事务绑定在当前线程 | `@Async` / 新线程中的代码不在原事务内 |
| 事务内不要做慢 IO | 调外部 HTTP、发 MQ 会长时间占用数据库连接和锁。用事务事件（下文）在提交后执行 |

### 传播行为（propagation）

| 值 | 含义 | 场景 |
|---|---|---|
| `REQUIRED`（默认） | 有事务就加入，没有就新建 | 绝大多数情况 |
| `REQUIRES_NEW` | 挂起当前事务，开一个新的独立事务 | 记录审计/失败日志，不随主事务回滚 |
| `NESTED` | 保存点（savepoint），可部分回滚 | 批处理中单条失败不影响整体 |
| `MANDATORY` | 必须在已有事务中调用 | 防御性约束 |

### 提交后再执行：事务事件

```java
@Transactional
public Long place(PlaceOrderRequest req) {
    ...
    events.publishEvent(new OrderPlaced(order.getId()));
    return order.getId();
}

@Component
class OrderNotifications {
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    void on(OrderPlaced e) {
        // 事务成功提交后才执行：发短信、发 MQ —— 避免“通知发出去了但数据回滚了”
    }
}
```

≈ Laravel 的 `DB::afterCommit()` / 事件监听器的 `$afterCommit = true`。

## 7. 并发扣库存的三种做法

| 方案 | 实现 | 适用 |
|---|---|---|
| 悲观锁 | `@Lock(LockModeType.PESSIMISTIC_WRITE)` → `SELECT ... FOR UPDATE` ≈ `lockForUpdate()` | 冲突频繁，单行热点 |
| 乐观锁 | 实体加 `@Version`，冲突时抛 `ObjectOptimisticLockingFailureException`，捕获后重试或提示 | 冲突较少，大多数场景 |
| 条件更新 | `update ... set stock = stock - ? where id = ? and stock >= ?`，看影响行数 | 简单计数，性能最好 |

```java
@Lock(LockModeType.PESSIMISTIC_WRITE)
@Query("select p from Product p where p.id = :id")
Optional<Product> findByIdForUpdate(Long id);
```

乐观锁冲突在全局异常处理器里转成 409：

```java
@ExceptionHandler(ObjectOptimisticLockingFailureException.class)
ProblemDetail conflict() {
    return ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT, "数据已被他人修改，请重试");
}
```

## 8. 不用 JPA 的时候

### JdbcClient：手写 SQL 的轻量方案

```java
@Repository
class ReportDao {
    private final JdbcClient jdbc;
    ReportDao(JdbcClient jdbc) { this.jdbc = jdbc; }

    List<DailySales> dailySales(LocalDate from, LocalDate to) {
        return jdbc.sql("""
                    SELECT date_trunc('day', created_at)::date AS day, sum(amount) AS total
                    FROM orders
                    WHERE created_at >= :from AND created_at < :to
                    GROUP BY 1 ORDER BY 1
                    """)
                .param("from", from)
                .param("to", to.plusDays(1))
                .query(DailySales.class)      // 列名自动映射到 record 字段
                .list();
    }
}
```

报表、复杂聚合、批量操作，直接写 SQL 比和 JPQL 较劲高效得多。同一个项目里 JPA（写模型）+ JdbcClient（读模型/报表）混用是很常见的 CQRS-lite 做法，二者共享同一个事务管理器。

### MyBatis：国内团队的常见选择

SQL 写在 Mapper XML 或注解里，结果映射到对象。没有持久化上下文、脏检查和懒加载，行为更接近“PDO + 映射”，对 PHP 背景的团队心智负担更小。如果团队 SQL 能力强、表结构复杂、需要精细调优，MyBatis（或 MyBatis-Plus）是务实的选择；如果领域模型复杂、偏 DDD，JPA 更合适。

## 9. 本章自测

1. 下面代码为什么在事务提交后没有更新数据库？

```java
@Transactional(readOnly = true)
public void touch(Long id) {
    products.findById(id).orElseThrow().rename("x");
}
```

2. `OrderController` 直接返回 `Order` 实体，开启 `open-in-view=false` 后报 `LazyInitializationException`，正确的修复方式是什么？
3. `place()` 中捕获了 `BusinessException` 并记录日志后返回 `null`，数据会回滚吗？

<details>
<summary>参考答案</summary>

1. `readOnly = true` 时 Hibernate 将 flush 模式设为 MANUAL，不做脏检查，修改不会写回。
2. 不是重新打开 OSIV，而是在 Service 的事务内用 `@EntityGraph`/`join fetch` 加载需要的关联，并转换为 DTO 返回。
3. 不会。异常没有抛出 `@Transactional` 方法，事务正常提交，已经执行的扣库存会被保存。要么不要吞异常，要么手动 `TransactionAspectSupport.currentTransactionStatus().setRollbackOnly()`。
</details>
