# 08 测试

## 1. 工具对照

| PHP | Java |
|---|---|
| PHPUnit | **JUnit 5/6 (Jupiter)** |
| PHPUnit assertions | **AssertJ**（流式断言，强烈推荐） |
| Mockery / Prophecy | **Mockito** |
| Laravel `RefreshDatabase` + SQLite | `@DataJpaTest`（事务回滚）+ **Testcontainers**（真实数据库） |
| `$this->getJson('/api/...')` | **MockMvc** / `RestTestClient` |
| `Http::fake()` | MockRestServiceServer / WireMock |
| Pest 数据集 | `@ParameterizedTest` |

`spring-boot-starter-test` 已包含 JUnit、AssertJ、Mockito、Spring Test。Spring Boot 4 中各技术的测试支持也拆成了独立模块，例如 `spring-boot-starter-webmvc-test`、`spring-boot-starter-data-jpa-test`。

## 2. 纯单元测试（最多、最快）

不启动 Spring，直接 `new`。构造器注入的回报就在这里：

```java
class ProductTest {

    @Test
    void 扣减库存成功() {
        var p = new Product("PHONE-1", "手机", new BigDecimal("1999.00"), 10);
        p.deductStock(3);
        assertThat(p.getStock()).isEqualTo(7);
    }

    @Test
    void 库存不足抛业务异常() {
        var p = new Product("PHONE-1", "手机", new BigDecimal("1999.00"), 2);
        assertThatThrownBy(() -> p.deductStock(5))
                .isInstanceOf(BusinessException.class)
                .hasMessageContaining("库存不足");
    }

    @ParameterizedTest
    @CsvSource({"0, 10", "5, 5", "10, 0"})
    void 各种扣减数量(int qty, int expectedLeft) {
        var p = new Product("A", "a", BigDecimal.ONE, 10);
        p.deductStock(qty);
        assertThat(p.getStock()).isEqualTo(expectedLeft);
    }
}
```

方法名可以用中文（或用 `@DisplayName`），测试报告可读性很好。

## 3. Mockito

```java
@ExtendWith(MockitoExtension.class)
class OrderServiceTest {

    @Mock ProductRepository products;
    @Mock OrderRepository orders;
    @InjectMocks OrderService service;

    @Test
    void 下单时扣减库存并保存订单() {
        var phone = new Product("PHONE-1", "手机", new BigDecimal("1999.00"), 10);
        when(products.findById(1L)).thenReturn(Optional.of(phone));
        when(orders.save(any(Order.class))).thenAnswer(inv -> inv.getArgument(0));

        service.place(new PlaceOrderRequest(List.of(new OrderLine(1L, 2))));

        assertThat(phone.getStock()).isEqualTo(8);
        verify(orders).save(argThat(o -> o.getItems().size() == 1));
    }
}
```

| Mockery | Mockito |
|---|---|
| `$m->shouldReceive('find')->with(1)->andReturn($p)` | `when(m.findById(1L)).thenReturn(Optional.of(p))` |
| `->once()` | `verify(m, times(1)).findById(1L)` |
| `->andThrow(...)` | `thenThrow(...)` |
| `Mockery::on(fn...)` | `argThat(...)` |

## 4. 切片测试：只启动需要的那部分 Spring

| 注解 | 启动内容 | 用途 |
|---|---|---|
| `@WebMvcTest(XxxController.class)` | MVC 层（Controller、Advice、Filter、Jackson），不含 Service/DB | 测路由、参数校验、JSON 格式、状态码 |
| `@DataJpaTest` | JPA + 数据源 + Flyway，每个测试结束后回滚 | 测 Repository 查询、映射 |
| `@JsonTest` | 只有 Jackson | 测序列化格式 |
| `@SpringBootTest` | 完整容器 | 端到端集成测试 |

```java
@WebMvcTest(ProductController.class)
class ProductControllerTest {

    @Autowired MockMvc mvc;
    @MockitoBean ProductService products;     // 替换容器里的 Bean（Boot 4 中替代已移除的 @MockBean）

    @Test
    void 参数非法返回422() throws Exception {
        mvc.perform(post("/api/products")
                        .contentType(MediaType.APPLICATION_JSON)
                        .content("""
                                {"name": "", "sku": "x", "price": -1, "stock": 1}
                                """))
                .andExpect(status().isUnprocessableEntity())
                .andExpect(jsonPath("$.errors.name").exists())
                .andExpect(jsonPath("$.errors.price").exists());
    }

    @Test
    void 查询商品() throws Exception {
        when(products.get(1L)).thenReturn(new Product("PHONE-1", "手机", new BigDecimal("1999.00"), 10));

        mvc.perform(get("/api/products/1"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.sku").value("PHONE-1"));
    }
}
```

## 5. 用真实数据库测试：Testcontainers

H2 内存库和 PostgreSQL / MySQL 方言不同（JSONB、窗口函数、锁行为），**Repository 和迁移脚本应该在真实数据库上测**。Testcontainers 会用 Docker 临时启动一个数据库容器：

```java
@DataJpaTest
@Testcontainers
class ProductRepositoryTest {

    @Container
    @ServiceConnection                          // 自动把容器的连接信息注入 spring.datasource.*
    static PostgreSQLContainer postgres = new PostgreSQLContainer("postgres:17-alpine");

    @Autowired ProductRepository repo;

    @Test
    void 条件扣减库存不会扣成负数() {
        var p = repo.save(new Product("A", "a", BigDecimal.ONE, 3));

        assertThat(repo.deductStockAtomically(p.getId(), 2)).isEqualTo(1);
        assertThat(repo.deductStockAtomically(p.getId(), 2)).isEqualTo(0);   // 剩 1，不够扣
    }
}
```

Testcontainers 2.x 中 PostgreSQL 模块的类位于 `org.testcontainers.postgresql` 包，Maven 坐标为 `org.testcontainers:testcontainers-postgresql`。

### 开发环境也可以复用

Spring Boot 支持在 `src/test/java` 中写一个“测试启动类”，用 Testcontainers 启动依赖后运行应用 —— 本地开发不再需要手动 `docker compose up`：

```java
@TestConfiguration(proxyBeanMethods = false)
class TestcontainersConfig {
    @Bean @ServiceConnection
    PostgreSQLContainer postgres() { return new PostgreSQLContainer("postgres:17-alpine"); }
}

public class TestShopApplication {
    public static void main(String[] args) {
        SpringApplication.from(ShopApplication::main).with(TestcontainersConfig.class).run(args);
    }
}
```

另外，项目根目录放一个 `compose.yaml` 并引入 `spring-boot-docker-compose`，`spring-boot:run` 时会自动启动其中的服务。

## 6. 测试金字塔建议

- 领域逻辑：大量纯单元测试（毫秒级）。
- Controller：`@WebMvcTest` 覆盖校验、错误码、JSON 契约。
- Repository：`@DataJpaTest` + Testcontainers，只测自定义查询。
- 少量 `@SpringBootTest` 端到端：下单主流程、安全配置。

`@SpringBootTest` 启动整个容器比较慢，Spring 会 **缓存测试上下文**：配置相同的测试类共享一个容器。滥用 `@MockitoBean` 会让每个测试类的上下文都不同、导致反复启动 —— 这是 Java 项目测试变慢的常见原因。
