# 10 生产化

## 1. 部署形态对比

| | PHP | Spring Boot |
|---|---|---|
| 产物 | 源代码目录 + vendor | 一个 fat jar（或 Docker 镜像） |
| 进程 | nginx + php-fpm | `java -jar app.jar`（内嵌 Tomcat） |
| 发布 | 切换软链 / 新容器，php-fpm reload | 滚动替换实例（启动需要几秒到几十秒） |
| 热更新 | 改文件即生效（OPcache 刷新后） | 不支持，必须重新部署 |
| 健康检查 | 自己写 `/health` | Actuator 内置 |
| 优雅停机 | php-fpm 自然完成 | `server.shutdown=graceful`（Boot 默认开启） |

## 2. Actuator：开箱即用的运维端点

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus
  endpoint:
    health:
      probes:
        enabled: true          # /actuator/health/liveness 与 /readiness，直接给 k8s 探针用
      show-details: when-authorized
```

| 端点 | 用途 |
|---|---|
| `/actuator/health` | 健康检查（自动包含数据库、Redis、磁盘等） |
| `/actuator/health/liveness`、`/readiness` | k8s 存活/就绪探针 |
| `/actuator/metrics` | JVM 内存、GC、线程、HTTP 请求耗时、连接池 |
| `/actuator/prometheus` | Prometheus 拉取格式（需 `micrometer-registry-prometheus`） |
| `/actuator/loggers` | **运行时调整日志级别**，无需重启 |
| `/actuator/threaddump`、`/heapdump` | 线上排查线程阻塞和内存泄漏 |

**安全提示**：`heapdump`、`env` 等端点包含敏感信息，只在内网端口暴露（`management.server.port: 8081`）或加认证。

## 3. 日志

Spring Boot 默认 SLF4J（门面）+ Logback（实现），≈ PSR-3 + Monolog。

```java
private static final Logger log = LoggerFactory.getLogger(OrderService.class);

log.info("order placed id={} user={}", order.getId(), userId);   // 用占位符，不要字符串拼接
log.error("payment failed orderId={}", id, e);                   // 异常放最后一个参数，会打印完整堆栈
```

结构化 JSON 日志（便于 ELK / Loki 采集）一行配置即可：

```yaml
logging:
  structured:
    format:
      console: ecs        # 或 logstash / gelf
```

第 05 章中 Filter 写入 MDC 的 `traceId` 会自动出现在每条日志里。

## 4. 可观测性：指标与链路追踪

- **Micrometer** 是指标门面（≈ 给 Prometheus/StatsD/Datadog 的统一 API），HTTP、JDBC 连接池、JVM 指标自动采集。
- 链路追踪使用 Micrometer Tracing + OpenTelemetry，自动在 HTTP 调用、消息中传播 trace 上下文。Spring Boot 4 提供 `spring-boot-starter-opentelemetry`。

自定义业务指标：

```java
@Service
class OrderMetrics {
    private final Counter placed;
    OrderMetrics(MeterRegistry registry) {
        this.placed = Counter.builder("shop.orders.placed").register(registry);
    }
    void onPlaced() { placed.increment(); }
}
```

## 5. 构建 Docker 镜像

方式一：不写 Dockerfile，用 Buildpacks：

```bash
./mvnw spring-boot:build-image -Dspring-boot.build-image.imageName=acme/shop:1.0.0
```

方式二：分层 Dockerfile（依赖层可被缓存，代码改动只重建最上层）：

```dockerfile
FROM eclipse-temurin:25-jre AS builder
WORKDIR /app
COPY target/*.jar app.jar
RUN java -Djarmode=tools -jar app.jar extract --layers --destination extracted

FROM eclipse-temurin:25-jre
WORKDIR /app
RUN useradd --system app
USER app
COPY --from=builder /app/extracted/dependencies/ ./
COPY --from=builder /app/extracted/spring-boot-loader/ ./
COPY --from=builder /app/extracted/snapshot-dependencies/ ./
COPY --from=builder /app/extracted/application/ ./
ENV JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75 -XX:+ExitOnOutOfMemoryError"
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

## 6. JVM 参数入门

| 参数 | 作用 | 建议 |
|---|---|---|
| `-XX:MaxRAMPercentage=75` | 堆上限占容器内存的比例 | 容器中用它代替 `-Xmx` |
| `-XX:+ExitOnOutOfMemoryError` | OOM 时直接退出，让编排系统重启 | 推荐 |
| `-XX:+HeapDumpOnOutOfMemoryError` | OOM 时生成堆转储 | 配合挂载卷排查 |
| `-XX:+UseZGC` | 低延迟 GC | 大堆、对停顿敏感时 |
| `-Xlog:gc*:file=gc.log` | GC 日志 | 排查性能问题 |

容器内存规划：堆只是一部分，还有 Metaspace、线程栈、直接内存、代码缓存。**容器限制 1GB 时，堆设 70%～75% 比较安全**。

## 7. 性能调优的第一顺序

1. **数据库**：N+1、缺索引、连接池大小（HikariCP 默认 10，通常 `核数 * 2` 附近即可，不是越大越好）。
2. **外部调用**：超时、并发调用（虚拟线程）、缓存。
3. **线程模型**：IO 密集型服务开启虚拟线程。
4. 最后才是 JVM/GC 参数。

线上排查工具：`jcmd <pid> Thread.print`（线程栈）、`jcmd <pid> GC.heap_info`、JDK Flight Recorder（`jcmd <pid> JFR.start`，几乎零开销的性能剖析，用 JDK Mission Control 打开）、Arthas（阿里开源，线上诊断神器）。

## 8. 启动速度

| 手段 | 效果 |
|---|---|
| 懒初始化 `spring.main.lazy-initialization=true` | 启动快，但失去“启动即发现配置错误”的优点，生产慎用 |
| CDS / AOT 缓存（Java 25 Project Leyden） | 启动时间显著缩短，零代码改动 |
| GraalVM Native Image | 毫秒级启动、内存小，但构建慢、反射需要配置；适合 Serverless/CLI |
