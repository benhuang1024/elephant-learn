## 1. 心智映射

| PHP 世界 | Python 世界 | 说明 |
|---|---|---|
| `php` / `phpenv` / `asdf` | **uv** + `.python-version` | uv 同时管解释器版本和依赖 |
| Composer | **uv** | 命令更接近 `npm`：`uv add`、`uv sync`、`uv run` |
| `composer.json` | **pyproject.toml** | 标准由 PEP 621 定义 |

## 2. 安装 uv 与 Python

macOS / Linux：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
uv --version
uv python install 3.14
```

uv 会把解释器装在自己的目录里，不污染系统 Python。进入任意工程后：

```bash
uv python pin 3.14        # 写 .python-version，团队共享
uv sync                   # 创建/更新 .venv 与 uv.lock 一致
```

> **不要**再手动 `python -m venv`、`source .venv/bin/activate` 再 `pip install`。
> `uv run <命令>` 会自动使用工程的 `.venv`，缺依赖会先同步。

## 3. pyproject.toml 逐段解读

以 [shop-api/pyproject.toml](../code/shop-api/pyproject.toml) 为例：

```toml
[project]
name = "shop-api"
version = "1.0.0"
requires-python = ">=3.14"
dependencies = ["fastapi>=0.162", "sqlalchemy>=2.1", ...]

[dependency-groups]
dev = ["pytest>=9.1", "mypy>=2.4", "ruff>=0.17"]

[build-system]
requires = ["uv_build>=0.9"]
build-backend = "uv_build"

[tool.uv.build-backend]
module-name = "shop"
module-root = "src"
```

| 段 | 作用 | PHP 类比 |
|---|---|---|
| `[project].dependencies` | 运行时依赖 | `composer.json` 的 `require` |
| `[dependency-groups].dev` | 仅开发/CI 依赖 | `require-dev` |
| `[build-system]` | 如何把项目打成 wheel | 无直接对应 |
| `[tool.*]` | 各工具的配置 | `phpstan.neon`、`.php-cs-fixer.php` |

常用命令：

```bash
uv add httpx                 # 加运行时依赖并写入 pyproject + lock
uv add --dev pytest          # 加开发依赖
uv remove httpx
uv sync --frozen             # CI：严格按 lock 安装，锁文件不一致就失败
uv run pytest                # 在工程环境中执行，不需要 activate
uv run python -m shop.main   # 模块方式执行
uv tree                      # 查看依赖树
uv lock --upgrade            # 更新 lock（有 review 意识地做）
```

## 4. 虚拟环境到底是什么

PHP-FPM 通常一台机器一个 PHP 版本 + 全局 Composer 包；Python 的惯例是**每个项目一个 `.venv`**：

```
shop-api/
├── .venv/              # 解释器 + 依赖，gitignore
├── uv.lock             # 精确版本，提交
├── pyproject.toml      # 约束，提交
└── src/shop/...
```

`.venv/bin/python` 与系统 `python3` 是两个解释器。排查“为什么 import 不到”时，先看：

```bash
uv run python -c "import sys; print(sys.executable); print(sys.path)"
```

## 5. ruff 与 mypy

本仓库三个工程统一配置：

```bash
uv run ruff check
uv run ruff format --check     # 本仓库只要求 lint，格式化可自行执行
uv run mypy src                # Django 工程是应用而非包，未强制 mypy
```

ruff 规则集：`E,F,I,UP,B,SIM,RUF`。其中 `RUF001-003`（全角标点歧义）被关闭，因为中文注释和文案需要全角标点。

mypy 在 `lang-basics` 与 `shop-api` 使用 `strict = true`：

```toml
[tool.mypy]
python_version = "3.14"
strict = true
warn_unreachable = true
```

严格模式会禁止隐式 `Any`、未标注函数、未检查的 `Optional`。一开始会痛，但这是 Python 里最接近 PHPStan level 9 的东西。

| 场景 | 命令 |
|---|---|
| 快速修 lint | `uv run ruff check --fix` |
| 只检查某文件 | `uv run mypy src/shop/order/service.py` |
| 看某条规则 | `uv run ruff rule B006` |
| 生成 HTML 类型报告 | `uv run mypy src --html-report mypy-report` |

## 6. IDE

- **PyCharm Professional**：对 Django、SQLAlchemy、FastAPI 的跳转最完整；调试器和数据库工具成熟。
- **VS Code**：安装 Python、Ruff、Mypy Type Checker 三个扩展即可。把解释器指向 `.venv/bin/python`。
- 无论哪个 IDE，都把 `ruff check` 与 `mypy` 配成保存时/提交前检查；不要依赖记忆。

## 7. 单文件脚本：PEP 723

Python 3.11+ 支持把依赖写进脚本注释，uv 会为它创建临时环境：

```python
# /// script
# requires-python = ">=3.14"
# dependencies = ["rich>=14.0"]
# ///
```

运行：

```bash
uv run scripts/hello.py
```

对应的 PHP 习惯是“一个文件 + 全局装好的包”。PEP 723 的好处是脚本可移植、依赖可复现，不需要为一个一次性任务建工程。

## 8. 常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: shop` | 没装项目或没用 src 布局路径 | `uv sync`；用 `uv run` 执行 |
| 依赖装了但 import 不到 | 用错解释器/IDE 指到系统 Python | 检查 `sys.executable` |
| `command not found: python` | 系统只有 `python3`，或 pyenv shim 失效 | 用 `uv run python`，别依赖裸 `python` |
| 锁文件冲突 | 多人改依赖未合并 lock | 重新 `uv lock` 并 review |
| mypy 报第三方库无类型 | 缺 `py.typed`/stubs | 安装 `types-*` 或局部 `ignore_missing_imports` |
