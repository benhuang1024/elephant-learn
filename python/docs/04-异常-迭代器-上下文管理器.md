# 04 异常、迭代器与上下文管理器

> **配套代码（lang-basics）**
> 异常层级 / 异常组 / `raise from`：[exceptions.py](../code/lang-basics/src/basics/exceptions.py)
> 生成器流水线 / `with`：[generators.py](../code/lang-basics/src/basics/generators.py)
> 测试：`tests/test_exceptions.py`、`tests/test_generators.py`

PHP 有异常、`yield` 生成器和 `finally`；Python 的差异在于 **异常链、`ExceptionGroup`、生成器作为默认惰性组件、上下文管理器协议** 更成体系。

## 1. 异常层级

```python
class ShopError(Exception):
    """业务异常基类，Web 层统一映射为 4xx。"""

class NotFound(ShopError):
    def __init__(self, resource: str, identifier: object) -> None:
        super().__init__(f"{resource} 不存在: {identifier}")
        self.resource = resource
        self.identifier = identifier

class Conflict(ShopError):
    pass

class InsufficientStock(Conflict):
    def __init__(self, sku: str, requested: int, available: int) -> None:
        super().__init__(f"库存不足 sku={sku}")
        self.sku = sku
        self.requested = requested
        self.available = available
```

设计原则：

1. **业务异常继承一个基类**，Web 层只处理基类，再按子类细分状态码。
2. 异常携带机器可读字段（`sku`、`requested`），而不是只拼字符串。
3. 不要把“参数错误”和“系统故障”混在一个层级：前者 400/422，后者 500。
4. 库代码抛标准异常（`ValueError`、`KeyError`），应用层包装成业务异常。

对照：

| PHP | Python |
|---|---|
| `\Exception` / `\RuntimeException` | `Exception` / `RuntimeError` |
| `catch (NotFoundException $e)` | `except NotFound as e` |
| `finally` | `finally` |
| `$previous` | `raise X from e` → `__cause__` |
| 多个独立错误 | `ExceptionGroup` + `except*` |

## 2. `raise from`：保留因果链

```python
def find_product(products: dict[str, str], sku: str) -> str:
    try:
        return products[sku]
    except KeyError as exc:
        raise NotFound("商品", sku) from exc
```

`__cause__` 会保留原始 `KeyError`，traceback 同时显示两层：

```
KeyError: 'SKU-404'
The above exception was the direct cause of the following exception:
NotFound: 商品 不存在: SKU-404
```

- 用 `from exc` 表示“由它导致”。
- 用 `from None` 隐藏内部细节（只在确定不泄漏敏感信息时）。
- 不要 `except Exception: pass`；至少记录并保留原因。

## 3. `add_note`：给异常补充上下文

3.11+：

```python
try:
    int(raw)
except ValueError as exc:
    exc.add_note(f"输入来自用户表单: {raw!r}")
    raise
```

`__notes__` 会出现在 traceback 末尾，适合加入请求 ID、用户、批次号等不影响异常类型的信息。

## 4. ExceptionGroup 与 `except*`

批量处理时，多个错误不应只报第一个：

```python
def validate_batch(values: list[str]) -> BatchResult:
    errors: list[Exception] = []
    for raw in values:
        try:
            ...
        except ValidationError as exc:
            errors.append(exc)
    if errors:
        raise ExceptionGroup("批量校验失败", errors)
```

捕获：

```python
try:
    validate_batch(values)
except* ValidationError as group:
    for error in group.exceptions:
        ...
```

规则：

- `except*` 只能处理 `ExceptionGroup`（或 `BaseExceptionGroup`）。
- `except*` 块里不能 `return` / `break` / `continue`；先收集再返回。
- 每个子组会继续匹配后续 `except*`。
- `asyncio.TaskGroup` 的失败会聚合成 `ExceptionGroup`，所以两者要一起理解。

在 Web 层通常把业务异常映射成 HTTP；批量导入/后台任务才需要 `except*`。

## 5. 生成器：惰性流水线

```python
def read_lines(lines: Iterable[str]) -> Iterator[str]:
    for line in lines:
        stripped = line.strip()
        if stripped and not stripped.startswith("#"):
            yield stripped

def parse_ints(lines: Iterable[str]) -> Iterator[int]:
    for line in lines:
        try:
            yield int(line)
        except ValueError:
            continue

def pipeline(raw: Iterable[str]) -> Iterator[int]:
    yield from running_total(parse_ints(read_lines(raw)))
```

特点：

- 调用生成器函数**不执行任何代码**，只创建对象；第一次 `next()` 才开始。
- 内存占用与输入长度无关，适合大文件、API 分页、无限序列。
- `yield from` 委托给子生成器，省掉手写循环。
- 生成器只能消费一次；需要重复用就重新创建。
- `list(generator)` 会一次性物化，等于放弃惰性。

PHP 对照：

```php
function readLines(iterable $lines): Generator {
    foreach ($lines as $line) {
        $line = trim($line);
        if ($line !== '' && $line[0] !== '#') {
            yield $line;
        }
    }
}
```

几乎一致；Python 的生态更倾向于把“流”贯穿到底（DB 游标、文件、HTTP 分页）。

## 6. 只消费需要的元素

```python
def take[T](items: Iterable[T], count: int) -> list[T]:
    result: list[T] = []
    iterator = iter(items)
    for _ in range(count):
        try:
            result.append(next(iterator))
        except StopIteration:
            break
    return result
```

配合无限生成器：

```python
def naturals() -> Iterator[int]:
    value = 0
    while True:
        yield value
        value += 1

take(naturals(), 5)   # [0, 1, 2, 3, 4]
```

`itertools.islice` 是标准库版本；手写一次能理解 `StopIteration` 的边界。

## 7. 上下文管理器 ≈ try/finally 的封装

```python
from contextlib import contextmanager

@contextmanager
def transaction(store: dict[str, int]) -> Iterator[dict[str, int]]:
    snapshot = store.copy()
    try:
        yield store
    except Exception:
        store.clear()
        store.update(snapshot)
        raise
```

使用：

```python
with transaction(store) as tx:
    tx["a"] = 2
```

- `with` 保证 `__exit__` 一定执行，即使块内抛异常。
- `@contextmanager` 把“进入/退出”写成一个生成器，yield 之前是进入，之后是退出。
- 数据库事务、文件、锁、临时目录、请求上下文都适合。

手写类协议：

```python
class Timer:
    def __enter__(self) -> "Timer": ...
    def __exit__(self, exc_type, exc, tb) -> None: ...
```

> 注意：`@contextmanager` 的异常处理默认**不会吞掉异常**；只有 `except` 里不重新抛出才会吞。吞异常前想清楚。

## 8. 标准库工具箱

### itertools

| 函数 | 用途 |
|---|---|
| `islice(it, n)` | 取前 n 个 |
| `chain(a, b)` | 拼接流 |
| `groupby(sorted_data, key=...)` | 分组（必须先排序） |
| `takewhile` / `dropwhile` | 按条件截断 |
| `product` / `combinations` | 笛卡尔积/组合 |
| `count` / `cycle` / `repeat` | 无限序列 |

### functools

| 函数 | 用途 |
|---|---|
| `lru_cache` / `cache` | 纯函数缓存 |
| `partial` | 预绑定参数 |
| `reduce` | 折叠（可读性通常不如循环） |
| `wraps` | 装饰器保留元数据 |
| `cached_property` | 每实例缓存属性 |
| `singledispatch` | 按类型分派（替代一长串 isinstance） |

## 9. 何时不用生成器

- 需要随机访问/多次遍历：用 list。
- 生成器里做副作用且依赖执行顺序：容易出隐蔽 bug。
- 异常发生在消费阶段而不是创建阶段：错误定位更远，日志要带上下文。
- 生成器跨越请求/连接生命周期：Session 关闭后再惰性查询会报错（ORM 常见坑，见 [08 章](08-数据访问与事务.md)）。
