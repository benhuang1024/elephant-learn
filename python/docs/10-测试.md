pytest 不只是 PHPUnit 的替代品，它更像“测试框架 + 依赖注入 + 插件系统”。fixture 是核心心智模型。

## 1. PHPUnit vs pytest

| PHPUnit | pytest |
|---|---|
| 测试类继承 `TestCase` | 普通函数 `test_*` |
| `setUp()` / `tearDown()` | fixture |
| `@dataProvider` | `@pytest.mark.parametrize` |
| `$this->assertSame()` | `assert a is b` / `assert a == b` |
| Mockery / PHPUnit Mock | `monkeypatch` / `unittest.mock` / 协议替身 |
| `phpunit.xml` | `pyproject.toml` 的 `[tool.pytest.ini_options]` |
| `--filter` | `-k` / `-m` / 文件路径 |
| 覆盖率需 Xdebug/PCOV | `pytest-cov` |

pytest 的断言直接用 Python `assert`，失败时自动展开表达式；不需要背几十个 `assertXxx`。

## 2. 最小测试

```python
from decimal import Decimal

from basics.money import Money


def test_quantize_half_up() -> None:
    assert Money(Decimal("19.995")).amount == Decimal("20.00")
```

运行：

```bash
uv run pytest
uv run pytest tests/test_money.py::test_quantize_half_up
uv run pytest -k "money or order"
uv run pytest -x --lf          # 第一个失败即停；先跑上次失败
uv run pytest -v
```

## 3. fixture：测试的依赖注入

```python
@pytest.fixture
def settings(tmp_path: Path) -> Settings:
    return Settings(
        db_url=f"sqlite+pysqlite:///{tmp_path / 'test.sqlite3'}",
        environment="test",
        seed_demo_data=False,
    )

@pytest.fixture
def app(settings: Settings) -> Iterator[FastAPI]:
    application = create_app(settings)
    Base.metadata.create_all(application.state.db.engine)
    yield application
    application.state.db.dispose()

@pytest.fixture
def client(app: FastAPI) -> Iterator[TestClient]:
    with TestClient(app) as test_client:
        yield test_client
```

- fixture 通过参数名注入（类型注解只是给人和 mypy 看）。
- `yield` 前是 setup，`yield` 后是 teardown，保证异常时也执行。
- 作用域：`function`（默认）、`class`、`module`、`session`。**默认作用域越小越安全**；数据库/容器用 `session` 要谨慎清理。
- `tmp_path` 是 pytest 内建的临时目录 fixture，每个测试独立。

### `conftest.py`

- 同目录及子目录的测试自动可用。
- 不要把所有 fixture 都堆进根 `conftest.py`；按模块拆。
- 不要在 conftest 里做有副作用的全局初始化。

### 常用内建 fixture

| fixture | 用途 |
|---|---|
| `tmp_path` | 临时目录 |
| `monkeypatch` | 临时改环境变量/属性/函数 |
| `capsys` | 捕获 stdout/stderr |
| `caplog` | 捕获日志 |
| `request` | 访问测试元信息 |
| `db`（pytest-django） | 允许数据库访问并事务回滚 |

## 4. 参数化

```python
import pytest

@pytest.mark.parametrize(
    ("raw", "expected"),
    [("1", 1), ("10", 10), (" 3 ", 3)],
)
def test_parse_quantity(raw: str, expected: int) -> None:
    assert parse_quantity(raw) == expected


@pytest.mark.parametrize("raw", ["0", "-1", "abc", ""])
def test_invalid_quantity(raw: str) -> None:
    with pytest.raises(ValidationError):
        parse_quantity(raw)
```

- 一组输入一个失败会单独报告。
- 用 `pytest.param(..., id="...")` 给用例命名。
- 不要用参数化掩盖“每个分支逻辑完全不同”；那种情况拆测试更清晰。

## 5. 异常与警告

```python
with pytest.raises(NotFound) as caught:
    find_product({}, "SKU-404")

assert isinstance(caught.value.__cause__, KeyError)
assert "SKU-404" in str(caught.value)

with pytest.warns(DeprecationWarning):
    old_api()
```

`pytest.raises` 的 `match=` 用正则匹配异常消息；生产测试里适度使用，过度匹配文案会让重构变脆。

## 6. monkeypatch 与 mock

### monkeypatch：临时替换

```python
def test_with_env(monkeypatch: pytest.MonkeyPatch) -> None:
    monkeypatch.setenv("DB_URL", "sqlite+pysqlite:///:memory:")
    settings = Settings()
    assert settings.db_url == "sqlite+pysqlite:///:memory:"


def test_clock(monkeypatch: pytest.MonkeyPatch) -> None:
    monkeypatch.setattr("shop.order.service.datetime", FakeDateTime)
```

测试结束自动还原。优先 monkeypatch 而不是手写 `setUp/tearDown`。

### mock：验证交互

```python
from unittest.mock import Mock

def test_sends_email() -> None:
    mailer = Mock()
    service = NotificationService(mailer)
    service.welcome("ben")
    mailer.send.assert_called_once_with("ben")
```

原则：

- **优先用假的实现（fake）**，例如内存仓储、FakeClock；mock 只用于边界（邮件、支付、外部 API）。
- 不要 mock 自己写的 Service 再断言调用次数，那是在测试实现而不是行为。
- 对第三方库的 mock 要集中封装，避免散落在测试里。

## 7. FastAPI TestClient

```python
from fastapi.testclient import TestClient

def test_health(client: TestClient) -> None:
    response = client.get("/health")
    assert response.status_code == 200
    assert response.json() == {"status": "UP"}
```

- `TestClient` 基于 httpx，不真正监听端口。
- `with TestClient(app) as client:` 会触发 `lifespan`；不进入上下文则不会。
- 认证：`client.get(..., auth=("admin", "admin123"))`（HTTP Basic）。
- 可以检查任意响应头：`X-Request-Id`、`X-Elapsed-Ms`、`Content-Type`。

接口测试的价值：

- 覆盖路由、依赖、序列化、异常处理、认证的完整链路；
- 比单元测试更接近用户；
- 用少量测试覆盖关键路径即可，不必为每个分支写接口测试。

### 依赖覆盖

```python
app.dependency_overrides[get_db] = lambda: fake_session
```

本仓库没有用覆盖 Session，而是**注入独立 Settings + 临时数据库**，这样测试走真实 SQLAlchemy，能发现映射/事务问题。依赖覆盖适合替换外部服务（支付、邮件）。

## 8. 测试数据库策略

| 策略 | 优点 | 缺点 |
|---|---|---|
| 每测试临时 SQLite 文件 | 隔离、可查、接近真实 | 比内存慢 |
| 内存 SQLite | 快 | 连接/事务差异，需 StaticPool |
| 事务回滚（pytest-django `db`） | 快、隔离 | 不能测提交后行为 |
| Testcontainers PostgreSQL | 最真实 | 需 Docker、较慢 |
| 共享开发库 | 快 | 污染、并发冲突，**不要** |

本项目：

- 单元/接口测试：每个测试一个临时 SQLite 文件（`tmp_path`），`Base.metadata.create_all`。
- 提交/回滚/乐观锁：真实 `commit()`，因此不能靠外层事务回滚；用独立 DB 隔离。
- PostgreSQL：Testcontainers，Docker 不可用自动 skip。

```python
@pytest.mark.skipif(not docker_available(), reason="Docker daemon 不可用")
def test_postgres_end_to_end() -> None:
    with PostgresContainer("postgres:17-alpine", driver="psycopg") as postgres:
        ...
```

CI 必须有 Docker，否则这个测试会静默跳过；在 CI 日志里检查 “skipped” 数量。

## 9. 事务与并发测试

```python
with factory() as first_session, factory() as second_session:
    first = first_session.get(Product, product_id)
    second = second_session.get(Product, product_id)

    first.stock = 1
    first_session.commit()                 # version 0 -> 1

    with pytest.raises(OptimisticLockConflict):
        ProductService(second_session).update(...)
```

测试要点：

- 用两个独立 Session 模拟两个请求；
- 显式 commit 制造版本冲突；
- 断言最终状态（库存不为负、订单只有一条）；
- 不要依赖 `sleep` 制造并发；用确定性的版本/锁。

## 10. 查询数测试（防 N+1）

```python
@contextmanager
def count_queries(engine: Engine) -> Iterator[list[str]]:
    statements: list[str] = []

    def before_cursor_execute(conn, cursor, statement, parameters, context, executemany):
        statements.append(statement)

    event.listen(engine, "before_cursor_execute", before_cursor_execute)
    try:
        yield statements
    finally:
        event.remove(engine, "before_cursor_execute", before_cursor_execute)
```

断言：

```python
assert len(naive) == 3       # 3 个订单各懒加载一次
assert len(eager) == 2       # 主表 + 批量 items
```

这比“页面感觉很快”可靠得多；列表接口、详情页、导出功能都值得加一条。

## 11. Django 测试

```python
@pytest.fixture
def customer(db: Any) -> Any:
    return get_user_model().objects.create_user(username="customer", password="customer123")

def test_create_and_update(api: APIClient, customer: Any) -> None:
    api.force_authenticate(user=customer)
    created = api.post("/api/products", {...}, format="json")
    assert created.status_code == 201
```

- `pytest-django` 提供 `db` fixture；不加它访问数据库会报错。
- `APIClient` 支持 `force_authenticate`、`force_login`。
- Django `Client` 适合测 Admin/模板；DRF `APIClient` 适合 JSON API。
- `call_command("seed_demo")` 可以直接测管理命令。

## 12. 异步测试

```python
# pytest-asyncio / anyio
@pytest.mark.anyio
async def test_fetch_all() -> None:
    assert await fetch_all_async([1, 2, 3]) == [1, 2, 3]
```

本仓库语言层用 `asyncio.run(...)` 在同步测试里跑，避免额外插件；工程化项目建议引入 `pytest-asyncio` 或 `anyio`，并明确 event loop 作用域。

## 13. 覆盖率

```bash
uv add --dev pytest-cov
uv run pytest --cov=shop --cov-report=term-missing --cov-report=html
```

- 覆盖率是**发现盲区**的工具，不是 KPI。
- 关键路径（认证、支付、库存、迁移）要求更高覆盖。
- 不要为了数字写无断言的测试。

## 14. CI 流水线

```yaml
- uv sync --frozen
- uv run ruff check
- uv run mypy src
- uv run pytest
```

建议再加：

- 矩阵：Python 3.14 / 3.14t（评估 free-threaded）。
- 服务：Docker（Testcontainers）。
- 迁移：在空库上 `alembic upgrade head`，再跑测试。
- 安全：依赖漏洞扫描（pip-audit / osv-scanner）。
- 契约：OpenAPI diff。

## 15. 常见坑

| 坑 | 表现 | 解决 |
|---|---|---|
| 测试互相污染 | 顺序变化就失败 | 每测试独立 DB/临时目录 |
| 共享 fixture 被修改 | 随机失败 | 默认 function scope；不要在 fixture 里返回共享可变对象 |
| mock 太深 | 重构即红、真实 bug 漏掉 | 只 mock 边界，业务用真实实现 |
| 只测 happy path | 线上 4xx/5xx | 覆盖认证、校验、冲突、回滚 |
| 断言日志文案 | 改文案即失败 | 断言结构化字段/状态码 |
| 用 sleep 等异步 | 慢且不稳 | 事件/轮询上限/确定性同步点 |
| Testcontainers 静默跳过 | CI 没真正测 Postgres | 显式检查 skip 数，CI 强制 Docker |
| 测试里建 Engine 不 dispose | 连接泄漏 | fixture teardown dispose |
