安全不是“加一个 JWT 库”，而是**认证、授权、输入、输出、配置、依赖、运维**的组合。本章按攻击面组织，代码示例与 `shop-api` 对齐。

## 1. 认证与授权的区别

| 概念 | 回答的问题 | 本项目 |
|---|---|---|
| 认证 Authentication | 你是谁？ | HTTP Basic → `current_user` |
| 授权 Authorization | 你能做什么？ | `require_admin` / 角色 |
| 会话 Session | 你的登录状态如何保持？ | 无状态，每次带凭证 |
| 审计 Audit | 你做了什么？ | 请求日志 + 后续可加审计表 |

常见错误：只做认证不做授权（任何登录用户都能删商品），或把授权写在 UI（后端仍可被直接调用）。

## 2. 密码存储

**永远不要存明文，也不要用 MD5/SHA1/无盐 SHA256。** 用专门的密码哈希：

```python
from pwdlib import PasswordHash

password_hash = PasswordHash.recommended()   # 当前推荐 Argon2
digest = password_hash.hash("admin123")
password_hash.verify("admin123", digest)     # True/False
```

特征：

- 自带随机盐；
- 可调计算成本（内存/时间）；
- 验证是恒定时间比较；
- 升级算法时可透明 rehash。

演示账号：

```python
_DEMO_USERS = {
    "admin": (_password_hash.hash("admin123"), "admin"),
    "customer": (_password_hash.hash("customer123"), "customer"),
}
```

> 这些账号只用于本地走查。生产必须从数据库/身份提供商读取，密码策略与轮换由 IdP 管理。

防止用户名枚举：

```python
if record is None:
    _password_hash.verify(password, _DEMO_USERS["admin"][0])   # 也消耗一次哈希
    return None
```

否则“用户不存在”会明显快于“密码错误”，攻击者可枚举账号。

## 3. 认证方式选型

| 方式 | 适合 | 缺点 |
|---|---|---|
| HTTP Basic | 内部工具、演示、脚本 | 每次传密码；必须 HTTPS |
| Session + Cookie | 同域 Web、Django Admin | 需要 CSRF 防护；跨域麻烦 |
| Bearer JWT | 前后端分离、移动端、服务间 | 撤销/失效复杂 |
| OAuth2 / OIDC | 第三方登录、企业 SSO | 流程复杂 |
| mTLS / 服务网格 | 服务间零信任 | 运维成本 |

### 本项目：HTTP Basic

```python
_basic = HTTPBasic(auto_error=False)

def current_user(credentials: Annotated[HTTPBasicCredentials | None, Depends(_basic)]) -> User:
    if credentials is None:
        raise Unauthorized()
    user = authenticate(credentials.username, credentials.password)
    if user is None:
        raise Unauthorized("用户名或密码错误")
    return user
```

- `auto_error=False` 让我们返回统一的 problem+json，而不是 FastAPI 默认格式。
- `Unauthorized` 带 `WWW-Authenticate: Basic`，符合 RFC。
- 必须走 HTTPS；否则 Base64 凭证可被截获。

### JWT（生产常见）

FastAPI 文档的标准做法：

```python
from fastapi.security import OAuth2PasswordBearer

oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

def current_user(token: Annotated[str, Depends(oauth2_scheme)]) -> User:
    payload = decode_jwt(token, key=PUBLIC_KEY, algorithms=["RS256"])
    ...
```

要点：

- 用非对称签名（RS256/ES256），公钥验证、私钥签发；不要用 `alg=none`。
- 校验 `exp`、`iss`、`aud`、`nbf`；不要只解 payload。
- Access token 短（5–15 分钟），Refresh token 长且可撤销。
- 撤销：短期 token + 黑名单/版本号；或改用不透明 token + 服务端会话。
- 不要把敏感数据放 JWT（payload 只是 Base64，不是加密）。
- 时钟偏移、密钥轮换、kid 选择都要设计。

本仓库未实现 JWT；文档不把未验证代码伪装成可运行示例。需要时按上述边界接入。

## 4. 授权放在依赖层

```python
def require_admin(user: Annotated[User, Depends(current_user)]) -> User:
    if not user.is_admin():
        raise Forbidden("该操作需要 ADMIN 角色")
    return user

CurrentUser = Annotated[User, Depends(current_user)]
AdminUser = Annotated[User, Depends(require_admin)]
```

路由：

```python
def delete_product(..., _admin: AdminUser) -> None: ...
```

优点：

- 权限规则与路由签名在一起，review 时可见；
- 不会出现“忘了写 if”；
- 测试覆盖 401/403 很直接。

复杂系统需要：

- **RBAC**：角色→权限；
- **ABAC**：属性（部门、租户、数据分类）；
- **对象级权限**：这个订单是否属于当前用户；
- **策略引擎**：OPA/Cedar（规模大时）。

对象级权限示例（本项目订单接口目前只要求登录，真实系统必须校验归属）：

```python
order = OrderService(session, settings).get(order_id)
if order.customer_name != user.username and not user.is_admin():
    raise Forbidden("无权访问该订单")
```

> 当前 `GET /api/orders/{id}` 为演示简化，未做归属校验；生产必须加。

## 5. 输入校验

Pydantic 在边界做：

```python
sku: str = Field(min_length=1, max_length=64)
price: Price = Field(gt=0, max_digits=12, decimal_places=2)
stock: int = Field(ge=0)
items: list[OrderLine] = Field(min_length=1, max_length=20)
```

原则：

- **白名单**：只接受已知字段，`extra="forbid"` 可拒绝多余字段（默认忽略）。
- 长度/范围/枚举全部约束；不要只在前端校验。
- 数字/日期由 Pydantic 转换，失败 400。
- 文件上传校验类型、大小、内容（魔数），不要只看扩展名。
- 富文本/HTML 做转义或 sanitize（如 bleach），防止 XSS。

## 6. 输出与序列化

- 响应模型只暴露必要字段；不要直接把 ORM 对象/内部配置返回。
- 错误信息不要包含堆栈、SQL、密钥、内部路径。
- 日志脱敏：密码、token、Authorization、身份证、银行卡。
- 列表接口注意越权：过滤条件必须包含租户/用户范围，不能只依赖前端传的 `tenant_id`。

## 7. SQL 注入与 ORM

SQLAlchemy/Django ORM 的参数绑定默认安全：

```python
session.scalars(select(Product).where(Product.sku == sku))
```

危险的是字符串拼接：

```python
# 不要
session.execute(text(f"SELECT * FROM products WHERE sku = '{sku}'"))

# 要
session.execute(text("SELECT * FROM products WHERE sku = :sku"), {"sku": sku})
```

排序字段、表名、列名不能参数化，必须用白名单映射：

```python
SORTABLE = {"name": Product.name, "price": Product.price}
column = SORTABLE.get(raw_sort, Product.name)
```

## 8. CORS

```python
if settings.cors_origins:
    app.add_middleware(
        CORSMiddleware,
        allow_origins=settings.cors_origins,
        allow_methods=["*"],
        allow_headers=["*"],
        expose_headers=["X-Request-Id", "X-Elapsed-Ms"],
    )
```

- `allow_origins=["*"]` + `allow_credentials=True` 是无效/危险的组合。
- 生产明确列出前端域名，按环境配置。
- CORS 是浏览器策略，不保护服务端到服务端调用；不要把它当认证。

## 9. CSRF

- 纯 Bearer/Basic 的无状态 API：不依赖 Cookie，CSRF 风险低。
- Session/Cookie 认证：必须启用 CSRF（Django 默认启用，DRF 的 SessionAuthentication 会校验）。
- `SameSite=Lax/Strict` 作为纵深防御，但不能替代 token。
- 不要为了“方便”全局 `@csrf_exempt`。

## 10. 安全响应头

反向代理/中间件配置：

| Header | 建议 |
|---|---|
| `Strict-Transport-Security` | 生产 HTTPS 后开启，含子域谨慎 |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` / CSP `frame-ancestors` | 防点击劫持 |
| `Content-Security-Policy` | 按前端资源收紧 |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | 关闭不需要的浏览器能力 |

Django 有 `SecurityMiddleware` 与 `SECURE_*` 设置；FastAPI 可用中间件或交给网关。

## 11. Django 的安全默认值

| 能力 | Django | FastAPI 需自建 |
|---|---|---|
| 密码哈希 | 内建（可切 Argon2） | pwdlib/passlib |
| CSRF | 内建中间件 | 无（Cookie 会话时自建） |
| SQL 注入防护 | ORM | SQLAlchemy 参数绑定 |
| 点击劫持 | `XFrameOptionsMiddleware` | 中间件/网关 |
| Admin 权限 | `is_staff`/`is_superuser` | 自建 |
| Session | 内建 | 自建/第三方 |
| 安全头 | `SecurityMiddleware` + 设置 | 中间件/网关 |

Django 的“电池 included”在安全上是优势；FastAPI 的自由度要求团队有明确基线。

## 12. 秘密与配置

- 秘密只来自环境变量/密钥管理（Vault、AWS Secrets Manager、K8s Secret），**不进仓库**。
- `.env` 只用于本地，加入 `.gitignore`；提交 `.env.example`。
- 启动时校验必需秘密，缺失直接失败（fail fast）。
- 轮换密钥要支持双密钥过渡（JWT/加密）。
- 日志/异常上报前脱敏；Sentry 等工具配置 `before_send`。
- 数据库账号最小权限：应用账号不能 DDL；迁移账号单独。

本仓库的 `DJANGO_SECRET_KEY` / `DB_URL` 都有开发默认值，生产必须覆盖。

## 13. 限流与防滥用

| 层级 | 手段 |
|---|---|
| 网关 | IP/租户限流、WAF、Bot 防护 |
| 应用 | 登录失败计数、验证码、令牌桶 |
| 资源 | 请求体大小、分页上限、查询超时 |
| 业务 | 下单幂等键、库存预占、风控规则 |

FastAPI 可用 slowapi/中间件；Django 可用 django-ratelimit。分布式环境用 Redis 计数，不要用进程内字典。

## 14. 依赖与供应链

- `uv.lock` 固定版本，CI `--frozen`。
- 定期 `pip-audit` / `osv-scanner` / Dependabot。
- 少装包；评估维护状态、下载量、许可证。
- 容器基础镜像固定 digest，定期重建。
- 不要在生产镜像里装编译工具链。

## 15. 多租户与越权

最常见的线上漏洞不是 SQL 注入，而是 **IDOR（越权访问对象）**：

```
用户 A 登录后请求 /api/orders/123，而 123 属于用户 B
```

防护：

1. 查询条件永远带租户/用户范围：`where(Order.customer_id == user.id)`。
2. 不要信任客户端传的 tenant_id；从 token/会话推导。
3. 写操作做归属校验，而不仅是“已登录”。
4. 管理端操作单独授权，且记录审计。
5. 测试覆盖“A 访问 B 的资源 → 403/404”。
