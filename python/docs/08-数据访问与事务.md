本章以 **SQLAlchemy 2.0+ typed ORM** 为主线。它是 Data Mapper + Unit of Work，和 Doctrine 同族，与 Eloquent 的 Active Record 有本质差异。

## 1. 技术选型地图

| PHP | Python | 定位 |
|---|---|---|
| PDO | DB-API（psycopg / sqlite3） | 驱动层 |
| Doctrine DBAL | SQLAlchemy Core | SQL 构造与执行 |
| Doctrine ORM（Data Mapper + UoW） | **SQLAlchemy ORM** | 全功能 ORM |
| Eloquent（Active Record） | Django ORM / Peewee / SQLModel | 模型自带 CRUD |
| Laravel Migrations | **Alembic** | 迁移 |
| Doctrine Migrations | Alembic | 迁移 |
| 连接池（FPM 下少见） | Engine + QueuePool | 进程级连接池 |
| 查询日志 | `echo=True` / `before_cursor_execute` | 调试与测试 |

本仓库两个 Web 工程的对照：

| | shop-api | django-shop |
|---|---|---|
| ORM | SQLAlchemy（Data Mapper） | Django ORM（Active Record） |
| 事务 | `Session.commit()` | `transaction.atomic()` |
| 迁移 | Alembic | `manage.py makemigrations` |
| 乐观锁 | `version_id_col` | 无内建，需要手动 |
| 风格 | Repository + Service | Model + Serializer + ViewSet |

## 2. Engine 与 Session

```python
class Database:
    def __init__(self, url: str, *, echo: bool = False) -> None:
        engine_kwargs: dict[str, Any] = {"echo": echo}
        if url.startswith("sqlite"):
            engine_kwargs["connect_args"] = {"check_same_thread": False}
            if ":memory:" in url:
                engine_kwargs["poolclass"] = StaticPool
        self.engine = create_engine(url, **engine_kwargs)
        self.session_factory = sessionmaker(
            bind=self.engine,
            autoflush=False,
            expire_on_commit=False,
        )
```

| 对象 | 生命周期 | 职责 |
|---|---|---|
| `Engine` | 进程级，一个 URL 一个 | 连接池、方言、事务工厂 |
| `Session` | 请求/用例级 | 身份映射、变更跟踪、事务 |
| `SessionFactory` | 进程级 | 创建 Session |

**Session ≈ Doctrine 的 EntityManager / JPA 的持久化上下文**，不是数据库连接本身。它持有：

- **Identity Map**：同一 Session 里 `get(Product, 1)` 两次返回同一对象。
- **Unit of Work**：记录新增/修改/删除，flush 时统一发 SQL。
- **事务边界**：commit/rollback。

请求级依赖：

```python
def get_db(request: Request) -> Iterator[Session]:
    database: Database = request.app.state.db
    yield from database.session()
```

`Session.close()` 会回滚未提交事务并释放连接；所以 Service 必须显式 commit。

### 连接池

```python
create_engine(url, pool_size=5, max_overflow=10, pool_pre_ping=True)
```

- `pool_pre_ping`：取连接前 ping 一次，避免数据库重启后的坏连接（有少量开销）。
- `pool_recycle`：防止中间件/数据库断开空闲连接（如 30 分钟）。
- 多 worker：`worker × (pool_size + max_overflow)` 要小于 DB 连接上限。

## 3. Typed ORM 模型

```python
class Product(Base):
    __tablename__ = "products"

    id: Mapped[int] = mapped_column(IdType, primary_key=True)
    sku: Mapped[str] = mapped_column(String(64), unique=True, nullable=False)
    name: Mapped[str] = mapped_column(String(200), nullable=False, index=True)
    price: Mapped[Decimal] = mapped_column(Numeric(12, 2), nullable=False)
    stock: Mapped[int] = mapped_column(nullable=False)
    version: Mapped[int] = mapped_column(BigInteger, nullable=False, default=0)

    __mapper_args__ = {
        "version_id_col": version,
        "version_id_generator": version_generator,
    }
```

- `Mapped[T]` + `mapped_column` 让 mypy 知道属性类型。
- `Base` 继承 `DeclarativeBase`，`Base.metadata` 是 Alembic 的入口。
- 主键类型 `BigInteger().with_variant(Integer, "sqlite")`：SQLite 的自增主键必须是 `INTEGER`。
- `Decimal` + `Numeric(12, 2)`：金额不要用 float。
- 领域方法（`deduct`）放在模型里，规则不散落。

### 关系与聚合

```python
class Order(Base):
    items: Mapped[list["OrderItem"]] = relationship(
        back_populates="order",
        cascade="all, delete-orphan",
        order_by="OrderItem.id",
    )

    def add_item(self, product: Product, quantity: int) -> None:
        product.deduct(quantity)
        ...
        self.items.append(item)
```

- `cascade="all, delete-orphan"`：保存/删除订单时级联处理明细。
- 明细保存 **SKU 与单价快照**：商品后续改名调价不影响历史订单。
- 聚合根负责一致性：总价与库存扣减在 `Order.add_item` 里完成。

### 懒加载的默认值

SQLAlchemy 关系默认 `lazy="select"`：访问 `order.items` 才发 SQL。这在 Web 序列化时非常危险：

- Session 关闭后再访问 → `DetachedInstanceError`；
- 列表 N 个订单 → N 次附加查询（N+1）；
- 异步 Session 下更严格。

解决：在查询处显式 `selectinload` / `joinedload`，见第 7 节。

## 4. Unit of Work：没有 `save()`

```python
def update(self, product_id: int, payload: ProductUpdate) -> Product:
    product = self.get(product_id)
    product.update(name=payload.name, price=payload.price, stock=payload.stock)
    self.session.commit()          # 没有 session.update()/save()
    return product
```

提交时 SQLAlchemy：

1. 检测 Session 中所有脏对象；
2. 按依赖顺序 flush（INSERT/UPDATE/DELETE）；
3. 生成 `UPDATE products SET ... WHERE id=... AND version=...`；
4. 提交事务。

与框架对照：

| 行为 | Eloquent | Doctrine | SQLAlchemy |
|---|---|---|---|
| 修改后保存 | `$model->save()` | 自动（flush） | 自动（flush） |
| 新建 | `Model::create()` | `persist()` | `session.add()` |
| 删除 | `$model->delete()` | `remove()` | `session.delete()` |
| 查询 | `Model::find()` | `find()` | `session.get()` |
| 事务 | `DB::transaction()` | `flush()+commit()` | `commit()` |

**不要**在每个 Service 方法里 `session.add(existing_object)`；对已持久化对象是多余的。

### `expire_on_commit=False` 的取舍

默认 `True`：commit 后对象属性过期，下次访问重新查库（保证读到最新值）。本项目设为 `False`：

- 响应序列化在 commit 之后，避免额外查询与 Detached 问题；
- 代价是 commit 后对象可能是旧值（例如数据库触发器/其他会话的修改）；
- 对“提交后立即返回自己刚写入的数据”的 API 是合理选择。

理解这个开关，比记住配置值重要。

## 5. 事务

### 一个用例一个事务

```python
def place(self, payload: PlaceOrderRequest) -> Order:
    order = Order(customer_name=payload.customer_name)
    try:
        for line in payload.items:
            product = self.session.get(Product, line.product_id)
            if product is None:
                raise NotFound("商品", line.product_id)
            order.add_item(product, line.quantity)
        self.session.add(order)
        self.session.commit()
    except StaleDataError as exc:
        self.session.rollback()
        raise OptimisticLockConflict() from exc
    except Exception:
        self.session.rollback()
        raise
    return order
```

任何一步失败（库存不足、商品不存在、乐观锁冲突）都会回滚：

- 已扣的库存恢复；
- 已插入的订单/明细消失；
- 不会出现“扣了库存但没订单”。

测试 [test_transactions.py](../code/shop-api/tests/test_transactions.py) 明确验证了这一点。

### 嵌套事务

- `session.begin_nested()` → SAVEPOINT，适合“部分失败不影响外层”。
- 不要在 Service 里随便嵌套 `begin()`；Session 已有事务时会报错。
- Web 端推荐：**依赖负责 Session，Service 负责 commit/rollback**，不在路由里写事务。

### 隔离级别

PostgreSQL 默认 READ COMMITTED；MySQL 默认 REPEATABLE READ。跨库迁移时要显式确认：

```python
engine = create_engine(url, isolation_level="REPEATABLE READ")
```

库存扣减这类“读-改-写”要么用乐观锁，要么用 `SELECT ... FOR UPDATE`（悲观锁），不能只依赖默认隔离级别。

## 6. 乐观锁

```python
version: Mapped[int] = mapped_column(BigInteger, nullable=False, default=0)

__mapper_args__ = {
    "version_id_col": version,
    "version_id_generator": version_generator,
}
```

```python
def version_generator(current: int | None) -> int:
    return 0 if current is None else current + 1
```

行为：

1. 读取时带出 `version`。
2. `UPDATE ... SET ..., version = version + 1 WHERE id = ? AND version = ?`。
3. 若 `rowcount == 0`，SQLAlchemy 抛 `StaleDataError`。
4. Service 捕获并转成 HTTP 409。

为什么不用“先查再比”：

```
请求 A: SELECT stock, version=0
请求 B: SELECT stock, version=0
A: UPDATE ... WHERE version=0  → 成功, version=1
B: UPDATE ... WHERE version=0  → 0 行, 冲突
```

数据库层面的比较是原子的，应用层的“查完再比”有竞态窗口。

对照：

| 方案 | 适用 | 代价 |
|---|---|---|
| 乐观锁 version | 冲突少、读多写少 | 冲突时重试 |
| 悲观锁 `FOR UPDATE` | 冲突多、强一致 | 锁等待、死锁风险 |
| 原子 SQL（`stock = stock - ? WHERE stock >= ?`） | 简单扣减 | 业务逻辑受限 |
| 队列串行化 | 高冲突热点 | 架构复杂 |

`version` 从 0 开始是为了与 Java `@Version` 对齐；SQLAlchemy 默认从 1 开始，所以用了自定义生成器。

## 7. N+1 与预加载

反例：

```python
orders = session.scalars(select(Order)).all()
for order in orders:
    len(order.items)       # 每个 order 一次 SELECT
```

1 + N 次查询。解决：

```python
from sqlalchemy.orm import selectinload

statement = (
    select(Order)
    .options(selectinload(Order.items))
    .order_by(Order.created_at.desc())
)
orders = session.scalars(statement).all()
```

- `selectinload`：先查主表，再用 `WHERE order_id IN (...)` 批量查关联，固定 2 条 SQL。
- `joinedload`：一条 SQL JOIN，适合一对一/多对一；一对多会放大结果集。
- `subqueryload`：另一种批量策略，通常 selectin 更优。
- `raiseload("*")`：禁止懒加载，开发期尽早暴露问题。

[test_queries.py](../code/shop-api/tests/test_queries.py) 用事件监听统计 SQL：懒加载 3 个订单触发 3 次查询，`selectinload` 固定 2 次。

### 序列化与 N+1

即使查询用了 `selectinload`，如果响应模型里又访问了未加载关系，仍会触发查询。原则：

- 查询层明确“这个用例需要哪些关系”；
- 响应模型只读已加载字段；
- 用测试统计查询数，防止回归。

## 8. Alembic 迁移

```bash
uv run alembic upgrade head
uv run alembic revision --autogenerate -m "add order status"
uv run alembic downgrade -1
uv run alembic current
```

目录：

```
migrations/
├── env.py
├── script.py.mako
└── versions/
    └── 0001_initial.py
```

`env.py` 做三件事：

1. 从 `Settings` 读取 `DB_URL`（与运行时同源）。
2. 导入所有模型，注册到 `Base.metadata`。
3. 配置 offline/online 迁移。

| Laravel | Alembic |
|---|---|
| `php artisan migrate` | `alembic upgrade head` |
| `migrate:rollback` | `alembic downgrade -1` |
| `migrate:status` | `alembic current` / `history` |
| `migrations` 表 | `alembic_version` 表 |
| PHP 写 schema | Python 脚本 + `sa` 类型 |
| `migrate:fresh` | 删库重建（开发） |

规则：

- 迁移文件提交到仓库，**只向前**；回滚也写成新的迁移（生产）。
- 生产禁止 `Base.metadata.create_all()`。
- Autogenerate 只是草稿：检查类型、索引、约束、数据迁移。
- 修改已有迁移只允许在未发布的开发分支。
- 迁移与应用发布解耦：先迁移（向后兼容），再发应用。

本项目的初始迁移用 `BigInteger().with_variant(Integer, "sqlite")`，保证 SQLite 自增与 PostgreSQL BIGINT 都正确。

## 9. SQLite 与 PostgreSQL

| 维度 | SQLite | PostgreSQL |
|---|---|---|
| 启动 | 零依赖，文件 | 需要服务/容器 |
| 并发写 | 单写者，锁库 | MVCC，高并发 |
| 类型 | 动态类型，约束较弱 | 严格类型 |
| 自增 | `INTEGER PRIMARY KEY` | `BIGSERIAL`/identity |
| JSON | JSON1 扩展 | JSONB + 索引 |
| 迁移 | 部分 ALTER 受限 | 完整 DDL |
| 生产 | 小工具/边缘场景 | 主流 |

开发用 SQLite 提高反馈速度，**上线前必须在 PostgreSQL 跑测试**。本仓库用 Testcontainers 在 Docker 可用时自动跑 PostgreSQL 冒烟测试（[test_postgres.py](../code/shop-api/tests/test_postgres.py)）。

Testcontainers 模式：

```python
with PostgresContainer("postgres:17-alpine", driver="psycopg") as postgres:
    settings = Settings(db_url=postgres.get_connection_url(), seed_demo_data=False)
    ...
```

没有 Docker 时 `skipif` 自动跳过，不会让本地开发报错；CI 里必须装上 Docker 让它真正执行。

## 10. 原生 SQL 的逃生口

ORM 不适合所有查询。SQLAlchemy Core：

```python
from sqlalchemy import text

rows = session.execute(
    text("SELECT sku, SUM(subtotal) AS revenue FROM order_items GROUP BY sku"),
).mappings().all()
```

也可以直接 `engine.connect()` + DB-API。原则：

- 报表/批量操作写 SQL，别硬拗 ORM；
- 参数必须绑定（`:sku`），不要字符串拼接；
- 返回 DTO，不返回 ORM 对象；
- 复杂 SQL 单独放 `reports.py` / `dao.py`，便于 DBA review。

Java 版的 `CatalogReportDao` 就是这种定位；Python 项目同样需要“SQL 优先”的通道。

## 11. 常见坑

| 坑 | 表现 | 解决 |
|---|---|---|
| Session 跨请求复用 | 数据串、内存涨、并发错 | 每请求一个 Session |
| 忘记 commit | 数据“写了但没了” | Service 明确提交；测试覆盖 |
| commit 后访问懒加载 | `DetachedInstanceError` | 预加载；`expire_on_commit=False` |
| N+1 | 列表页慢 | `selectinload` + 查询计数测试 |
| 直接返回 ORM | 懒加载/泄漏/循环 | 响应模型 |
| 用 float 存金额 | 精度错误 | `Numeric` + Decimal |
| `create_all` 上生产 | schema 漂移 | Alembic |
| 每请求 create_engine | 连接耗尽 | 进程级 Engine |
| SQLite 并发写 | `database is locked` | 换 PostgreSQL / 串行写 |
| 乐观锁不重试 | 用户看到 409 | 前端提示重试或后端有限重试 |
