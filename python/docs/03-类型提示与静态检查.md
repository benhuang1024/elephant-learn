## 1. 定位：类型提示不是运行时约束

```python
def add(a: int, b: int) -> int:
    return a + b

add("1", "2")      # "12"，运行时不会阻止
```

Python 注解默认只是元数据。真正的检查发生在：

1. **静态检查器**：mypy / pyright 在 CI 与 IDE 里检查。
2. **运行时校验库**：Pydantic / msgspec 在边界（HTTP、配置、消息）解析数据。
3. **开发者的纪律**：内部代码信任类型提示，不做重复校验。

对照 PHP：

| PHP | Python |
|---|---|
| 原生类型声明在运行时会强制 | 注解默认不强制 |
| PHPStan 读注解做静态分析 | mypy / pyright 做同样的事 |
| `declare(strict_types=1)` | 无等号；靠静态检查与运行时库 |
| 泛型只在注释里 | 泛型语义被 mypy 完整检查（运行时仍擦除） |

> 结论：**边界用 Pydantic，内部用类型提示 + mypy**。这正是 `shop-api` 的做法。

## 2. 基础语法

```python
from collections.abc import Iterable, Sequence
from decimal import Decimal
from typing import Literal, TypedDict

product_id: int = 1
price: Decimal = Decimal("19.90")
name: str | None = None                    # 3.10+ 联合类型
ids: list[int] = [1, 2, 3]
by_sku: dict[str, int] = {"A": 1}
point: tuple[float, float] = (1.0, 2.0)
labels: set[str] = {"new"}
rows: Sequence[str]                          # 只读序列（list/tuple 都可）
values: Iterable[int]                        # 只要求可迭代

Status = Literal["PENDING", "PAID"]          # 字面量联合
```

| 写法 | 含义 |
|---|---|
| `T | None` | 可选（等价 `Optional[T]`） |
| `Literal["A", "B"]` | 只能是这些字面量 |
| `Final` | 不可重新赋值（仅检查器） |
| `ClassVar` | 类变量，不是实例字段 |
| `Any` | 放弃检查；strict 会拦截大量隐式 `Any`，显式 `Any` 应尽量避免 |
| `object` | 什么都不是，但可以赋给任何东西 |
| `Never` | 不可能有值（抛异常/死循环） |

## 3. 严格模式

`pyproject.toml`：

```toml
[tool.mypy]
python_version = "3.14"
strict = true
warn_unreachable = true
files = ["src"]
```

`strict = true` 打开的主要开关：

- 未标注的函数参数/返回值报错（`disallow_untyped_defs`）。
- 隐式 `Any` 报错（`disallow_any_generics`、`warn_return_any`）。
- `Optional` 未收窄就使用报错（`strict_optional`）。
- 重写方法签名不兼容报错。

运行：

```bash
uv run mypy src
```

迁移存量项目时不要一步到 strict：先 `mypy --ignore-missing-imports`，再逐模块加 `strict`，用 `# type: ignore[code]` 标注历史遗留（必须带错误码，避免吞掉新错误）。

## 4. 泛型：PEP 695 新语法

3.12 起不再需要 `TypeVar` 变量：

```python
class Repository[T: HasId]:
    def __init__(self) -> None:
        self._items: dict[int, T] = {}

    def get(self, item_id: int) -> T | None:
        return self._items.get(item_id)

def first[T](items: Iterable[T]) -> T | None:
    return next(iter(items), None)

type ProductId = int
```

对应的旧写法（老项目常见）：

```python
T = TypeVar("T", bound=HasId)
class Repository(Generic[T]): ...
```

| 概念 | PHP 世界 |
|---|---|
| `Repository[Product]` | `@template T` 注释 |
| `T: HasId` | `@template T of HasId` |
| `type ProductId = int` | `@phpstan-type` |
| 运行时擦除 | 同样擦除 |
| `type[T]` 参数 | `class-string<T>` |

泛型的价值不在运行时，而在**调用点检查**：`Repository[Product]` 里放 `Order` 会被 mypy 拒绝。完整示例见 [generics.py](../code/lang-basics/src/basics/generics.py)。

## 5. TypedDict：给关联数组上类型

PHP 的关联数组在 Python 里是 `dict[str, object]`，类型信息全丢。`TypedDict` 描述固定键：

```python
class ProductRow(TypedDict):
    sku: str
    name: str
    price_cents: int
    stock: int

def total_value(rows: list[ProductRow]) -> int:
    return sum(row["price_cents"] * row["stock"] for row in rows)
```

- 运行时仍是普通 dict，零开销。
- 少了键、类型不符，mypy 报错。
- 需要可选键用 `NotRequired` / `total=False`。

对比：

| 方案 | 运行时开销 | 校验 | 适合 |
|---|---|---|---|
| `dict[str, object]` | 无 | 无 | 临时数据 |
| `TypedDict` | 无 | 仅静态 | 解析后的 JSON/DB 行 |
| Pydantic `BaseModel` | 有 | 运行时 | HTTP/消息边界 |
| dataclass | 低 | 仅静态（可加 `__post_init__`） | 领域对象 |

## 6. Literal、重载与收窄

```python
from typing import Literal, overload

def parse(value: str, mode: Literal["int", "float"]) -> int | float:
    return int(value) if mode == "int" else float(value)

@overload
def get(key: str) -> str: ...
@overload
def get(key: str, default: str) -> str: ...
def get(key: str, default: str | None = None) -> str | None:
    ...
```

`isinstance` / `is None` / 字面量比较会触发**类型收窄**：

```python
def label(status: OrderStatus | None) -> str:
    if status is None:
        return "未知"
    match status:
        case OrderStatus.PAID:
            return "已支付"
        case _:
            return "其他"
```

## 7. Protocol 做依赖倒置

```python
class Clock(Protocol):
    def now(self) -> datetime: ...

class ExpiryPolicy:
    def __init__(self, clock: Clock) -> None:
        self.clock = clock
```

测试里传 `FakeClock`，生产传 `SystemClock`，无需继承。详见 [shapes.py](../code/lang-basics/src/basics/shapes.py) 与 [02 章](02-面向对象与数据建模.md#6-protocol结构化子类型)。

## 8. 常见严格模式报错

| 报错 | 含义 | 修法 |
|---|---|---|
| `Missing return statement` | 有分支没返回 | 补 `raise` 或返回 |
| `Item "None" ... has no attribute` | 可选值未判空 | `if x is None: return` |
| `Need type annotation` | 空容器无法推断 | `items: list[Product] = []` |
| `Returning Any` | 第三方库返回 Any | 显式 `cast` 或加类型保护 |
| `Incompatible override` | 子类签名不兼容 | 调整签名或用 `@override` |
| `Unused "type: ignore"` | 忽略注释已无效 | 删除，保持干净 |

`# type: ignore` 必须带错误码：`# type: ignore[assignment]`。否则框架升级后真正的错误会被吞掉。

## 9. 类型检查在 CI 中的位置

```yaml
# 伪代码
- uv sync --frozen
- uv run ruff check
- uv run mypy src
- uv run pytest
```

顺序建议：ruff（秒级）→ mypy（秒到分钟）→ pytest。失败信息越早越便宜。

## 10. Pyright / basedpyright

mypy 是默认选择，pyright 更快、对部分新语法支持更早。两者不必同时用；团队选一个，写进 CI 与编辑器。

| 维度 | mypy | pyright |
|---|---|---|
| 速度 | 中 | 快 |
| 严格模式 | `strict` | `strict` |
| 插件生态 | Pydantic/SQLAlchemy 等 | 部分内建 |
| 编辑器 | 需扩展 | VS Code 内建 |

本仓库统一用 mypy（`lang-basics`、`shop-api`）。

## 11. 类型与运行时校验的分界

```python
# 边界：Pydantic 负责解析、校验、错误格式
class ProductCreate(BaseModel):
    sku: str = Field(min_length=1, max_length=64)
    price: Decimal = Field(gt=0, max_digits=12, decimal_places=2)

# 内部：信任类型，不做重复校验
def create(self, payload: ProductCreate) -> Product:
    product = Product(sku=payload.sku, price=payload.price, ...)
```

不要在每个 Service 方法里再 `isinstance` 一遍；那是把类型系统当摆设，又增加维护成本。
