# 11 答疑锦囊

> 孩子的问题经常出人意料。这里收集了 30 个最可能被问到的问题。回答的原则是：**先用港口说一句，再用真话说一句**。

## 1. 关于电脑和云

1. **云在天上吗？**
   港口说：不在天上，在地上很大的“电脑仓库”里。真话：在数据中心里。叫“云”是因为画图时习惯用一朵云代表“远处很多电脑”。
2. **服务器长什么样？**
   真话：像一个扁扁的铁盒子，一层一层插在高高的铁架子（机柜）上，没有屏幕，风扇呼呼地吹。可以给孩子看数据中心的图片。
3. **为什么服务器不关机？**
   港口说：港口 24 小时营业，晚上也有人要买东西。真话：网站随时有人访问，所以服务器一直开着。
4. **阿里云的电脑会坏吗？**
   会。所以要把箱子分散在好几块场地上，甚至好几个码头区（可用区）。

## 2. 关于集装箱

5. **箱子里真的有东西吗？**
   真话：箱子里是程序文件和它需要的工具，它们都是电脑里的数据，不是看得见摸得着的东西。
6. **箱子有多大？**
   真话：小的几兆字节（几张照片那么大），大的几个吉字节（一部电影那么大）。
7. **一个程序为什么要装进箱子？直接放不行吗？**
   港口说：奇形怪状的货很难搬，换个地方就放不下。真话：程序换一台电脑经常跑不起来，装进箱子后，到哪台电脑上都一样。
8. **箱子会被偷看吗？**
   港口说：每个箱子都关得严严实实，看不到隔壁箱子。真话：容器之间是隔离的，但隔离不是绝对的，所以还需要很多安全措施。
9. **设计图丢了怎么办？**
   设计图存在档案馆（镜像仓库）里，档案馆会备份。所以重要的是：**每张设计图都要存进档案馆**。

## 3. 关于调度中心

10. **K8s 为什么叫 K8s？**
    Kubernetes 的 K 和 s 中间有 8 个字母，就写成 K8s。就像有人把“国际化 internationalization”写成 i18n。
11. **调度员会不会放错位置？**
    真话：它按规则打分，比如“哪块场地空位多”“这个箱子需要放在有冷藏的场地”。规则是人定的，规则不对，放的位置就可能不合适。
12. **巡查员会累吗？**
    不会。它是一个程序，可以一直不停地工作。
13. **账本丢了怎么办？**
    账本会抄好几份放在不同的地方。全丢了就很麻烦，所以要定期备份。用 ACK 的话，这件事由阿里云负责。
14. **谁来指挥调度中心？**
    你（写订单的人）。但你不直接指挥调度员和巡查员，你只是把订单交给服务窗口。

## 4. 关于托盘、窗口和贴纸

15. **为什么叫 Pod？**
    Pod 在英文里是“豆荚”的意思，一个豆荚里可以装几颗豆子（容器）。我们的故事里把它叫作托盘。也可以顺便讲讲豆荚，但只用一个类比，不要混着讲。
16. **托盘里最多能放几个箱子？**
    没有严格的上限，但一般只放 1 个，最多放 2–3 个必须在一起的。
17. **取货窗口是一个真的人吗？**
    不是。它是一条“指路规则”，写在每块场地的指路牌上。
18. **如果所有托盘都坏了，窗口怎么办？**
    窗口找不到能用的托盘，顾客就买不到东西了（网站打不开）。所以要放好几个托盘，并且分散在不同的场地。
19. **贴纸可以贴好几张吗？**
    可以。一个托盘可以贴“红色”“冰淇淋”“新口味”好几张贴纸，窗口可以按任意组合来找。

## 5. 关于自愈、扩容和更新

20. **坏了的箱子能修好吗？**
    电脑里的箱子坏了不修，直接扔掉换一个新的，因为照着设计图做一个新的很快。
21. **为什么不一次全部换成新的？**
    全部一起换，那段时间就没有人卖东西了。一个一个换，一直都有人在卖。
22. **如果新口味很难吃怎么办？**
    马上换回旧口味，这叫“回滚”。港口会记住以前的口味。
23. **箱子可以无限增加吗？**
    不行。场地的空位有限，满了就要租新场地。而且每个箱子都要花钱。
24. **人少了为什么要减少箱子？**
    为了省钱。空着的箱子也在用场地，场地是要付钱的。

## 6. 关于数据和网络

25. **箱子里的东西为什么会丢？**
    因为箱子坏了就被扔掉，换来的新箱子是照设计图新装的，里面只有设计图上写的东西。
26. **网站上我买的东西会丢吗？**
    不会。重要的数据（比如订单）都存在仓库（数据库和持久存储）里，箱子换了，仓库里的东西还在。
27. **门牌号为什么会变？**
    换了新托盘，新托盘就会领到一个新的门牌号。所以我们用名字找它，就像存电话号码时写名字一样。

## 7. 关于 ACK 和其他

28. **ACK 和 K8s 是一个东西吗？**
    K8s 是调度中心的“管理方法”，谁都可以免费用。ACK 是阿里云按照这个方法帮你开好、管好的调度中心。
29. **我以后能做这个吗？**
    能。学好数学和英语，长大可以学编程。很多工程师就是从搭积木、玩游戏开始喜欢上电脑的。
30. **我可以在自己家电脑上开一个小港口吗？**
    可以。有一些工具（比如 kind、minikube）能在一台电脑上开一个迷你港口，长大一点可以试试。

## 附：每个类比“哪里不像”汇总

讲完一个类比，挑一条告诉孩子，防止他们把类比当成事实。

| 类比 | 像的地方 | 不像的地方 |
|---|---|---|
| 云服务器 = 商场铺位 | 租来用，按时间付钱 | 云服务器通常是一台大机器“分”出来的一小块；可以随时释放 |
| 容器 = 集装箱 | 标准化，到哪都能运 | 容器坏了不修，直接扔掉重建；容器之间共享同一个操作系统内核 |
| 镜像 = 设计图 | 照它能做出很多一样的东西 | 镜像是分层的，几张设计图可以共用同一层 |
| 集群 = 港口 | 很多场地，统一管理 | 港口在一个地方；集群的节点可以分布在好几个机房 |
| apiserver = 服务窗口 | 所有事情都从这里办 | 没有人在排队，每秒可以处理成千上万个请求 |
| etcd = 总账本 | 记录所有事情 | 一定要多副本，靠一种“投票”规则保证每份账本都一样 |
| 控制器 = 巡查员 | 发现不对就纠正 | 不是走路巡逻，账本一变就马上收到通知 |
| Pod = 托盘 | 一起搬、一起放 | 托盘建好后基本不能改，要改就换新的 |
| Service = 取货窗口 | 地址固定 | 不是一个人或程序，只是每个节点上的转发规则 |
| Secret = 上锁的信封 | 用来放秘密 | 默认只是编码，有权限的人一看就懂，需要额外加密 |
| Namespace = 片区 | 分开管理，名字可以重复 | 默认没有围墙，Pod 之间可以互相访问 |
| PV = 仓库 | 东西长期保存 | 删除申请单时，仓库可能连东西一起被拆掉 |
| ACK = 阿里云帮你管调度中心 | 省心 | 节点、应用、权限和费用仍然是你的责任 |
