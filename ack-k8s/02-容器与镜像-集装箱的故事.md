# 02 容器与镜像：集装箱的故事

## 1. 一句话说清

**把程序和它需要的所有东西装进一个标准的“集装箱”，这个箱子放到哪台电脑上都能一模一样地跑起来。**

## 2. 港口故事

> 很久以前，没有集装箱。船要运货的时候，工人得把一袋袋大米、一箱箱香蕉、一台台自行车一件一件搬上船。每种货的形状都不一样，搬得又慢又容易坏。到了下一个港口，还要一件一件搬下来。
>
> 后来，有人发明了**集装箱**：一个大小统一的铁箱子。不管里面装的是大米还是自行车，外面都是一样的箱子。吊车只需要会吊“箱子”这一种东西，船只需要会放“箱子”这一种东西。运货一下子变快了好多倍。
>
> 电脑里的程序也有同样的烦恼。小红在自己电脑上写好了一个小游戏，拿到小明的电脑上却打不开：“缺少某某文件”“版本不对”。程序就像那些形状各异的货物，换一台电脑就水土不服。
>
> 于是程序员也发明了“集装箱”，叫**容器**。程序和它需要的所有东西（用到的工具、文件、设置）一起装进箱子。箱子外面是标准的，所以放在任何一台装了“吊车”（容器引擎）的电脑上都能跑。
>
> 那么箱子是怎么装出来的？要先画一张**设计图**，写清楚“箱子里放什么、怎么摆”。这张设计图叫**镜像**。照着同一张设计图，可以装出很多个一模一样的箱子。
>
> 设计图要找个地方保存，方便别人取用。存放设计图的地方叫**镜像仓库**，就像港口的**设计图档案馆**。阿里云的设计图档案馆叫 **ACR**。

## 3. 低年级简化版

- 程序换一台电脑就可能打不开，就像形状奇怪的货物不好搬。
- 我们把程序装进一个标准的箱子里，这个箱子叫“容器”。
- 箱子到哪里都能用，就像集装箱放到哪艘船上都行。

## 4. 大人要懂的真相

### 4.1 三个概念

| 概念 | 是什么 | 港口类比 | 类比 Java/PHP |
|---|---|---|---|
| 镜像 Image | 只读的、分层的文件系统包 + 启动命令 | 设计图 + 打包清单 | 类 Class |
| 容器 Container | 镜像运行起来的一个实例，有自己的进程、网络、文件系统视图 | 照设计图装好、正在运输的集装箱 | 对象 Object |
| 镜像仓库 Registry | 存放和分发镜像的服务 | 设计图档案馆 | Maven 中央仓库 / Packagist |

一张镜像可以启动任意多个容器，这和一个类可以 `new` 出很多个对象是一样的道理。

### 4.2 容器不是虚拟机
- **虚拟机**：每台都有一个完整的操作系统，就像每个箱子里都塞了一整艘小船。
- **容器**：共享宿主机的 Linux 内核，用 namespace 做隔离（看不见别人）、用 cgroup 做限额（不能多吃资源）。所以容器启动只要几秒，体积小。

### 4.3 一个 Dockerfile 就是一张设计图
仓库里的 Java 示例项目就有一个：[java/code/shop-api/Dockerfile](../java/code/shop-api/Dockerfile)。

```dockerfile
# 第一阶段：在“工厂”里把程序编译出来
FROM eclipse-temurin:25-jdk AS build
WORKDIR /workspace
COPY .mvn .mvn
COPY mvnw pom.xml ./
RUN ./mvnw -q -DskipTests dependency:go-offline
COPY src src
RUN ./mvnw -q -DskipTests package

# 第二阶段：只把成品装进一个更小的箱子
FROM eclipse-temurin:25-jre
WORKDIR /app
RUN useradd --system --uid 10001 app
COPY --from=build /workspace/target/shop-api-*.jar app.jar
USER app
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

每一行都是设计图上的一步：`FROM` 选底座，`COPY` 放东西进去，`RUN` 在箱子里干活，`ENTRYPOINT` 写“箱子打开以后先做什么”。

### 4.4 常用命令

```bash
docker build -t shop-api:1.0.0 .          # 照设计图画出镜像
docker run -p 8080:8080 shop-api:1.0.0    # 用镜像装出一个箱子并运行
docker ps                                  # 看正在运行的箱子
docker tag shop-api:1.0.0 <ACR地址>/<命名空间>/shop-api:1.0.0
docker push <ACR地址>/<命名空间>/shop-api:1.0.0   # 把设计图存进档案馆
```

### 4.5 阿里云 ACR
- **个人版**：免费，适合学习。
- **企业版**：收费，支持镜像安全扫描、全球同步、P2P 加速分发等，适合生产。
- 同一地域内，ACK 节点从 ACR 拉镜像要走 **VPC 内网地址**（域名里通常带 `-vpc`），这样更快，也不产生公网流量费。

## 5. 类比在哪里不成立

- 真正的集装箱坏了会修；容器坏了**直接扔掉，再按设计图装一个新的**。这是容器世界非常重要的习惯，叫“不可变基础设施”。
- 真正的集装箱里的货是一直在的；容器里写进去的文件，**箱子一删就没了**（除非挂了持久卷，见 06 章）。
- 镜像是“分层”的：好几张设计图可以共用同一个底座层，下载过的层不用再下载。真实的设计图没有这个特点。

## 6. 课堂小活动：照设计图装箱子（10 分钟）

1. 老师画一张“设计图”贴在黑板上：一个纸杯里放 2 颗红色积木、1 颗蓝色积木。
2. 请 3 个同学上来，每人按设计图装一个纸杯。
3. 问大家：这 3 个杯子一样吗？（一样）这说明了什么？（同一张设计图能装出很多个一模一样的箱子）
4. 老师把其中一个杯子“打翻”，问：要怎么办？引导孩子说出“照设计图再装一个”，而不是“把积木捡起来修”。

## 7. 孩子可能会问

- **问：为什么叫“镜像”？是镜子吗？**
  答：不是镜子。这里的“镜像”是“一模一样的副本”的意思。用设计图做出来的每个箱子，都是一模一样的“镜像”。
- **问：一个箱子里能装几个程序？**
  答：可以装好几个，但习惯上**一个箱子只装一个主要的程序**，这样坏了好换，也好管理。
- **问：那只鲸鱼是什么？**
  答：Docker 是最出名的一种装箱工具，它的标志是一头背着集装箱的鲸鱼。

## 8. 自测题

1. 镜像和容器是什么关系？用“类和对象”解释一遍。
2. 为什么容器比虚拟机启动快？
3. 多阶段构建（multi-stage build）有什么好处？
4. ACK 拉取同地域 ACR 镜像时，为什么要用 VPC 地址？

<details>
<summary>参考答案</summary>

1. 镜像是模板（类），容器是镜像运行起来的实例（对象），一个镜像可以启动多个容器。
2. 容器共享宿主机内核，不需要启动一个完整的操作系统，只是启动一个被隔离的进程。
3. 编译工具（JDK、Maven）只留在构建阶段，最终镜像只包含运行需要的 JRE 和 jar，体积小，攻击面也小。
4. 走内网更快、更稳定，不产生公网流量费用，也不需要节点有公网出口。
