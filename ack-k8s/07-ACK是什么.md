# 07 ACK 是什么

> 本章的事实核对于 2026-10，链接都指向阿里云官方文档。ACK 的产品形态和价格经常调整，动手前请再看一眼原文。

## 1. 一句话说清

**ACK 就是阿里云帮你盖好、管好港口调度中心。你只要租场地、下订单，调度中心坏了、要升级了，都是阿里云的事。**

## 2. 港口故事

> 自己开一个港口很累：要盖调度中心、雇服务窗口的人、准备总账本（还要抄好几份防丢）、请调度员和巡查员。调度中心半夜出了问题，你还得爬起来修。
>
> 阿里云说：“调度中心我来帮你开，我来帮你管。我在好几个码头区都放了调度中心的分身，一个坏了另一个马上顶上。你只要告诉我你要几块场地，然后像以前一样下订单就行。”
>
> 这个服务就叫 **ACK**，全称是“容器服务 Kubernetes 版”（Alibaba Cloud Container Service for Kubernetes）。
>
> 港口的场地还是要你自己租（就是 ECS 云服务器），按场地收钱。还有一种更省心的玩法，叫**虚拟场地**：你连场地都不用租，直接把托盘交给阿里云，托盘放多久就付多久的钱。
>
> 港口外面的路（负载均衡）、仓库（云盘、NAS）、设计图档案馆（ACR）、监控摄像头（日志和监控），阿里云也都准备好了，可以直接接到你的港口上。

## 3. 低年级简化版

- 开港口很累，阿里云说“调度中心我帮你管”。
- 你只要租场地、下订单。
- 这个帮忙管港口的服务，叫“容器服务”。

## 4. 大人要懂的真相

### 4.1 ACK 的几种形态

| 形态 | 一句话 | 港口类比 | 现状（2026-10） |
|---|---|---|---|
| **ACK 托管集群 Pro 版** | 控制面由阿里云托管、高可用，有可赔付的 SLA | 阿里云帮你管调度中心，还签了服务合同 | **生产首选** |
| ACK 托管集群基础版 | 控制面托管，但规模小、没有 SLA | 免费的小调度中心，只给学习用 | 不收集群管理费；每个账号最多 2 个集群，每个集群最多 10 个 Worker 节点，配额不能提高；可以热迁移到 Pro 版 |
| ACK 专有集群 | 控制面装在你自己的 ECS 上，自己运维 | 调度中心你自己盖、自己管 | **已于 2024-08-21 停止新建**（云盒场景除外） |
| ACK Serverless 集群 | 不用管节点，按 Pod 用量付费 | 只有虚拟场地的港口 | **2025-02-17 起对新用户关闭创建入口**，替代方案是 ACS 集群，或在 ACK Pro 中使用 ACS 算力 |
| ACK Edge | 云边一体，管理边缘机房和设备上的节点 | 总港口管着很多偏远的小码头 | 物联网、门店、CDN 边缘 |
| ACK One（分布式云容器平台） | 统一管理多地域、多云、自建机房里的集群 | 港口联盟总部 | 混合云、多集群、容灾 |
| ACK 灵骏版 | 面向灵骏智算集群的托管 K8s | 专门停万吨巨轮的港口 | 大模型训练和推理 |

来源：[ACK 产品简介](https://help.aliyun.com/zh/ack/product-overview/product-introduction)、[ACK Pro 版集群概述](https://help.aliyun.com/zh/ack/overview-of-ack-pro-clusters)、[ACK Serverless 关闭新建入口公告](https://help.aliyun.com/zh/ack/product-overview/product-change-announcement-on-deprecation-of-cluster-creation-interface-for-ack-serverless-clusters)、[产品变更公告列表](https://help.aliyun.com/zh/ack/product-overview/product-changes/)。

**结论：学习用基础版或者小规格的 Pro 版；生产用 Pro 版。** 本教材的实验都按 **ACK 托管集群** 来写。

### 4.2 Pro 版 vs 基础版

| | Pro 版 | 基础版 |
|---|---|---|
| SLA | 地域级集群 99.95%，可用区级集群 99.50% | 无 |
| 规模 | 默认每个账号 100 个集群、每个集群 5000 个节点，可以申请提高 | 每个账号 2 个集群、每个集群 10 个节点，不能提高 |
| 集群管理费 | 按集群收取（可以用资源包抵扣） | 不收 |
| 其他费用 | 节点 ECS、负载均衡、云盘、日志服务等，按各产品单独计费 | 同左 |
| 适合 | 生产和正式测试环境 | 个人学习、测试 |

### 4.3 自建 K8s vs ACK 托管

| 你要操心的事 | 自建（kubeadm 等） | ACK 托管 |
|---|---|---|
| apiserver/etcd/scheduler 高可用 | 自己部署 3 个 master，自己做负载均衡 | 阿里云负责，跨可用区 |
| etcd 备份与恢复 | 自己做 | 阿里云负责 |
| 控制面升级 | 自己按步骤一个个升 | 控制台一键升级（节点池另外升级） |
| 和云产品打通 | 自己装 CCM、CSI、CNI 插件 | 内置：负载均衡、云盘/NAS/OSS、Terway |
| 节点 | 自己的机器 | ECS 节点池（也能接入 ECS 以外的机器，见 ACK One） |
| 你还要负责 | 全部 | 节点、应用、权限配置、成本 |

### 4.4 ACK 和其他阿里云产品的关系

```
            用户 ──► ALB / CLB / NLB（负载均衡）──► Ingress / Service
                                                      │
 ACR（镜像仓库）──镜像──► ┌──────── ACK 集群 ────────┐  │
                        │ 托管控制面（阿里云负责）     │◄─┘
 RAM（账号权限）──身份──► │ 节点池：ECS                │──► 云盘 / NAS / OSS（存储）
                        │ 虚拟节点：ECI / ACS 算力    │──► RDS / Tair / Elasticsearch（托管中间件）
                        └───────────────────────────┘
                                  │
                                  └──► SLS 日志服务、ARMS / Prometheus 监控
```

| 产品 | 在 ACK 里的作用 | 港口类比 |
|---|---|---|
| ECS | Worker 节点 | 场地 |
| ECI / ACS | Serverless 容器算力，通过虚拟节点接入 | 虚拟场地 |
| ACR | 镜像仓库 | 设计图档案馆 |
| CLB / NLB | `type: LoadBalancer` 的 Service 会自动创建（四层） | 港口外面修的专用道路 |
| ALB | ALB Ingress（七层、全托管、配置热更新） | 港口大门和导航牌 |
| 云盘 / NAS / OSS | 持久卷 | 仓库 |
| RAM | 阿里云账号与权限，再和 K8s RBAC 结合 | 港口通行证 |
| SLS | 日志采集与检索 | 港口的监控录像 |
| ARMS / 托管 Prometheus | 指标监控与告警 | 港口的仪表盘 |
| RDS / Tair | 托管 MySQL、PostgreSQL、Redis 兼容缓存 | 港口外面专业公司开的大仓库 |

### 4.5 Kubernetes 版本
- ACK 的版本号格式是 `x.y.z-aliyun.n`：`x.y.z` 是社区版本，`n` 是 ACK 的补丁序号。
- 从 1.31 开始，ACK 支持每一个社区小版本，每个版本的维护期是一年。截至 2026-10，版本页列出的可用版本是 1.34–1.36；**1.35 起不再支持 cgroup v1**。
- 版本停止维护前要安排升级：先升级控制面，再升级节点池。
- 来源：[ACK 支持的 Kubernetes 版本](https://help.aliyun.com/zh/ack/ack-managed-and-ack-dedicated/user-guide/support-for-kubernetes-versions/)

### 4.6 怎么估算一个学习集群的费用
1. **集群管理费**：基础版为 0；Pro 版看官方价格页。
2. **节点**：比如 2 台 4 核 8 GB 的按量付费 ECS（14 章的 Magento 至少需要这么多）。
3. **负载均衡**：每个 `LoadBalancer` Service 或 ALB 实例都单独计费。
4. **NAT 网关 + EIP**：创建集群时如果勾选“为专有网络配置 SNAT”，会创建 NAT 网关，这也收费。
5. **云盘、NAS、日志服务**：按用量计费。

**做完实验，删除集群时要勾选“同时删除负载均衡、云盘等关联资源”，然后去 ECS、负载均衡、NAT 网关、云盘控制台各检查一遍。**

## 5. 类比在哪里不成立

- “阿里云帮你管调度中心”不等于“阿里云帮你管一切”。**节点的系统补丁、应用的安全、RBAC 怎么授权、费用花多少，仍然是你的责任**（这叫“责任共担模型”）。
- 虚拟场地并不是真的没有机器，只是机器由阿里云管理，你看不到，也不用为空闲的部分付钱。
- 托管控制面你**看不到 master 节点**：`kubectl get nodes` 只会列出 Worker 节点。

## 6. 课堂小活动：谁管什么（5 分钟）

在黑板上画两栏：“阿里云管”“我自己管”。老师念卡片，孩子举手说放哪栏：
调度中心（阿里云）、总账本抄几份（阿里云）、租几块场地（我）、箱子里装什么（我）、订单写几个托盘（我）、调度中心的分身坏了换新的（阿里云）、谁可以进港口（我）、每个月付多少钱（我）。

## 7. 孩子可能会问

- **问：阿里云帮我们管，要不要钱？**
  答：基础版的调度中心不要钱，但场地要钱。Pro 版的调度中心要另外付管理费，因为阿里云承诺它“几乎不会坏”，坏了还会赔钱。
- **问：除了阿里云，别的公司也有吗？**
  答：有。腾讯云有 TKE，华为云有 CCE，亚马逊有 EKS，谷歌有 GKE，微软有 AKS。它们都是同一个 Kubernetes，所以学会一个，其他的也会了。

## 8. 自测题

1. ACK 托管集群和专有集群的根本区别是什么？现在新建集群还能选专有集群吗？
2. 学习用选哪种集群？生产用选哪种？各自的理由是什么？
3. ACK Serverless 集群现在还能新建吗？想用 Serverless 容器算力应该怎么做？
4. 使用 ACK 托管集群时，哪些事情仍然是你的责任？
5. 删除一个实验集群后，还可能有哪些资源在继续扣费？

1. 托管集群的控制面由阿里云运维，专有集群的控制面部署在用户自己的 ECS 上、由用户运维。专有集群已于 2024-08-21 停止新建（云盒场景除外）。
2. 学习用基础版（免管理费，但最多 10 个节点，没有 SLA）或小规格的 Pro 版；生产用 Pro 版（有可赔付的 SLA，规模大，能力更全）。
3. 从 2025-02-17 起，新用户不能创建；存量用户不受影响。新用户可以创建 ACS 集群，或者在 ACK Pro 集群中通过虚拟节点使用 ACS 算力。
4. 节点操作系统和组件升级、应用和镜像安全、RAM 与 RBAC 授权、网络访问控制、数据备份、成本控制。
5. 没有勾选一起删除的负载均衡（CLB/NLB/ALB）、NAT 网关和 EIP、云盘和快照、NAS 文件系统、日志服务 Project、ACR 企业版实例。
