# 00 写给老师：怎么用这套教材

> 这一章是写给你的，不用讲给孩子。读完你会知道：每章怎么读、类比怎么讲、讲到什么程度算够。

## 1. 每章的结构

从 01 到 09，每章都是同样的 8 个小节：

| 小节 | 给谁看 | 用途 |
|---|---|---|
| 1. 一句话说清 | 孩子 | 下课前让孩子能复述的那一句 |
| 2. 港口故事 | 孩子 | 类比的主体，可以直接念 |
| 3. 低年级简化版 | 1–3 年级的孩子 | 3–5 句话，不出现任何英文 |
| 4. 大人要懂的真相 | 你 | 真实的概念、命令、YAML，用来回答追问 |
| 5. 类比在哪里不成立 | 你 + 孩子 | 讲完类比，挑一两条告诉孩子 |
| 6. 课堂小活动 | 孩子 | 5–10 分钟，动手或者角色扮演 |
| 7. 孩子可能会问 | 你 | 提前想好的答案 |
| 8. 自测题 | 你 | 检查自己有没有真的懂 |

10–12 章是纯教学材料；13–14 章是给你自己做的实战，不用讲给孩子。

## 2. 讲类比的 5 条原则

1. **先讲故事，再说名词。** 先讲“港口里有个调度员”，等孩子听懂了再说“它的真名叫 Scheduler”。一上来就说名词，孩子会把它当成要背的东西。
2. **一次只引入一个新词。** 一节课最多 3–4 个新名词。每个新名词都要在黑板上贴一张卡片：左边画港口里的东西，右边写真名。
3. **始终用同一个类比世界。** 全书只用“集装箱港口”。如果这节课说 Pod 是托盘，下节课又说 Pod 是房间，孩子就乱了。
4. **讲清类比在哪里不成立。** 类比只是帮你走进门的梯子，不是房子本身。每讲完一个类比，挑一条“不像的地方”说出来，比如：“真的港口里，集装箱坏了要修；但电脑里的集装箱坏了直接扔掉，再装一个新的。”这能防止孩子把类比当成事实。
5. **让孩子当里面的角色。** 小学生对“我是调度员”的记忆，比对“调度员负责安排位置”的记忆深得多。10 章的教案大部分是角色扮演。

## 3. 讲到什么程度算够

| 年级 | 目标 | 不要讲 |
|---|---|---|
| 1–3 年级 | 知道“程序可以装进箱子，有个聪明的管理员帮忙放箱子，坏了会自己换” | 英文名词、IP、端口、YAML |
| 4–6 年级 | 能说出 5–8 个角色（集装箱、设计图、港口、调度员、巡查员、场地、托盘、取货窗口）及它们的真名；能解释“自愈”和“扩容” | 网络插件、存储类、权限细节 |
| 兴趣班 / 初中 | 能看懂一个简单的 YAML，知道每一行在“下什么订单” | 生产环境的安全加固、成本优化 |

## 4. 你自己要懂到什么程度

你要比你讲的**多懂一层**。孩子问“为什么”的时候，你能再往下说一句真相。这套教材里“大人要懂的真相”这一节就是这一层。

一个检验方法：**合上书，在白纸上画出 03 章的流程图**（你下订单 → 服务窗口 → 总账本 → 调度员 → 场地管理员 → 集装箱跑起来），并且能说出每一步对应的真名。画得出来，就可以去上课了。

## 5. 推荐教具

- 纸杯或乐高积木：当“集装箱”
- 托盘或硬纸板：当“Pod 托盘”
- 彩色圆点贴纸：当“标签 Label”
- 一个笔记本：当“总账本 etcd”
- 几块地垫或用粉笔画的方格：当“场地 Node”
- CNCF 的绘本《Phippy 和朋友们》（The Illustrated Children's Guide to Kubernetes），网上可以免费看：<https://www.cncf.io/phippy/>。它的类比是“长颈鹿和朋友们”，和本教材的港口不一样，**建议只拿来当课后读物**，不要和港口类比混着讲。
