# 06 存储与网络

## 1. 一句话说清

**集装箱里的东西是临时的，要长期保存的东西得放进港口的仓库；港口里每个托盘都有自己的门牌号，大家靠门牌号和名字互相找到对方。**

## 2. 港口故事

> **仓库的故事。** 冰淇淋托盘每天都会记账：“今天卖了 100 个。”可是托盘坏了一换，新托盘的账本是空白的，之前的账全丢了！
>
> 所以港口建了**仓库**。重要的东西不放在箱子里，而是放进仓库。托盘坏了，新托盘接着用同一个仓库，账本还在。
>
> 怎么借仓库呢？你要填一张**借仓库申请单**：“我要一个 20 平方米、放得进冰箱的仓库。”港口管理处看了看自己有哪几种**仓库规格**：“普通仓库”“冷藏仓库”“大家都能同时进的共享仓库”，挑一种合适的，马上给你盖一个，然后把钥匙交给你的托盘。
>
> 注意：普通仓库一次只能有一个托盘进去，冷藏仓库也是；只有**共享仓库**能让好几个托盘同时进去拿东西。
>
> **门牌号的故事。** 港口里每个托盘都有一个**门牌号**（IP 地址），托盘之间可以直接按门牌号寄信。可是托盘一换，门牌号就变了。所以大家更习惯记**名字**：港口有一本**电话簿**（DNS），你说“我要找冰淇淋窗口”，电话簿就告诉你它现在的门牌号。
>
> 港口里铺设门牌号和道路的施工队叫**网络插件**。不同施工队修路的方式不一样，阿里云自己的施工队叫 **Terway**。

## 3. 低年级简化版

- 箱子里的东西箱子一换就没了，重要的东西要放进仓库。
- 每个托盘都有门牌号，但是会变。
- 所以我们用名字找人，港口有一本电话簿。

## 4. 大人要懂的真相

### 4.1 存储三件套

| 对象 | 是什么 | 港口类比 | 谁来写 |
|---|---|---|---|
| PersistentVolume (PV) | 一块真实的存储（一块云盘、一个 NAS 目录） | 一间仓库 | 通常自动创建 |
| PersistentVolumeClaim (PVC) | 应用对存储的申请 | 借仓库申请单 | 开发者 |
| StorageClass | 存储的“规格类型”，以及如何自动创建 PV | 仓库规格表 | 平台（ACK 预置了几种） |

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: data
spec:
  accessModes: ["ReadWriteOnce"]
  storageClassName: alicloud-disk-topology-alltype
  resources:
    requests:
      storage: 20Gi
```

### 4.2 访问模式

| accessModes | 含义 | ACK 上常见的存储 |
|---|---|---|
| ReadWriteOnce (RWO) | 只能被一个节点读写挂载 | 云盘（ESSD 等） |
| ReadWriteMany (RWX) | 多个节点同时读写 | NAS、CPFS |
| ReadOnlyMany (ROX) | 多个节点只读 | OSS（ossfs） |

### 4.3 ACK 上的存储选择

| 存储 | 适合 | 注意 |
|---|---|---|
| 云盘 | 数据库、单副本有状态服务 | **只能挂到同一可用区的节点**；一次只能挂一个节点；有最小容量（ESSD 一般 20GiB 起） |
| NAS | 多副本共享文件（Magento 的 `pub/media`、上传目录） | 按用量计费；小文件密集读写性能一般 |
| OSS | 静态资源、备份、大文件 | 不是 POSIX 文件系统，不适合频繁随机写 |

ACK 预置的 StorageClass 名字会随版本变化，以 `kubectl get storageclass` 的输出为准。常见的有 `alicloud-disk-topology-alltype`（推荐，按可用区延迟绑定）、`alicloud-disk-essd`；开启 CNFS 后还有 `alibabacloud-cnfs-nas`。

**云盘的大坑：`lost+found`。** 新格式化的 ext4 云盘根目录有一个 `lost+found` 文件夹。MySQL、PostgreSQL 初始化时发现数据目录“不是空的”，会拒绝启动。解决办法是挂载到子目录（`subPath`），或者把数据目录设到子目录（PostgreSQL 的 `PGDATA`），13、14 章的 YAML 里都处理了。

### 4.4 网络模型的三条规则

1. 每个 Pod 有自己的 IP；
2. 所有 Pod 之间不经过 NAT 就能直接通信（跨节点也一样）；
3. 节点和 Pod 之间可以直接通信。

这三条规则由 **CNI 网络插件**来实现。ACK 提供两种（**创建集群时选定，创建后不能更换**）：

| | Terway（阿里云自研） | Flannel（社区开源） |
|---|---|---|
| Pod IP | 直接使用 VPC 里的地址（弹性网卡 ENI） | 独立的 Pod 网段，和 VPC 网段不同 |
| NetworkPolicy | 支持 | 不支持 |
| 性能 | 更好，支持 eBPF 加速 | 一般 |
| 规划难度 | 要给 Pod 预留足够的 vSwitch 地址 | 简单 |
| 适合 | 生产、需要网络隔离、大规模 | 小规模、学习 |

### 4.5 服务发现：CoreDNS

```bash
# 在任意 Pod 里
nslookup hello-nginx                              # 同一个 Namespace
nslookup hello-nginx.default.svc.cluster.local    # 完整名字
```

应用里连数据库写 `jdbc:postgresql://postgres:5432/shop`，而不是写某个 IP。13 章就是这样写的。

### 4.6 NetworkPolicy：给片区修围墙
默认情况下所有 Pod 之间都能互通。用 NetworkPolicy 可以只放行需要的流量（需要 Terway）：

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: postgres-allow-app, namespace: shop }
spec:
  podSelector: { matchLabels: { app: postgres } }
  policyTypes: ["Ingress"]
  ingress:
    - from:
        - podSelector: { matchLabels: { app: shop-api } }
      ports:
        - port: 5432
```

## 5. 类比在哪里不成立

- 真实仓库盖好了就在那里；云盘 PV 删除 PVC 时，按 `reclaimPolicy` 可能**连数据一起删掉**（ACK 动态创建的云盘默认是 Delete）。重要数据要设成 Retain，或者做好快照。
- 真实仓库在哪都能去；云盘**只能挂给同一可用区的节点**。Pod 被调度到别的可用区，就挂不上了。
- “门牌号会变”是对的，但 Service 的虚拟 IP（ClusterIP）在 Service 存在期间是不变的，变的是 Pod IP。

## 6. 课堂小活动：仓库与电话簿（10 分钟）

1. **箱子会丢东西**：请一位同学当“冰淇淋托盘”，在一张便利贴上记账“卖了 3 个”，贴在自己身上。老师宣布“托盘坏了”，换一位同学，问：账还在吗？（不在）
2. **用仓库**：再来一次，这次把账记在讲台上的“仓库本子”里。换人以后，新同学去仓库本子上接着记。
3. **电话簿**：在黑板上写一个“电话簿”：`冰淇淋窗口 → 3 号座位`。冰淇淋托盘换了座位后，只改电话簿，其他同学照着电话簿就能找到它。

## 7. 孩子可能会问

- **问：为什么不把所有东西都放仓库？**
  答：仓库要钱，而且去仓库拿东西比在箱子里拿慢。只有“丢了会心疼”的东西才放仓库。
- **问：门牌号为什么会变？**
  答：因为托盘换了一个新的，新托盘就会领到一个新的门牌号。所以我们用名字来找它，不要背门牌号。

## 8. 自测题

1. PV、PVC、StorageClass 的关系是什么？
2. Magento 有 3 个 Web 副本，都要读写 `pub/media`，应该选云盘还是 NAS？为什么？
3. 为什么 MySQL 挂载新云盘时会启动失败？怎么解决？
4. Terway 和 Flannel 的主要区别是什么？集群建好后还能换吗？
5. 同一个集群里，`shop` 命名空间的应用想访问 `db` 命名空间里叫 `postgres` 的 Service，地址怎么写？

<details>
<summary>参考答案</summary>

1. PVC 是应用的申请，StorageClass 描述如何创建存储，系统按 StorageClass 自动创建满足 PVC 的 PV 并绑定。
2. NAS。云盘是 ReadWriteOnce，只能被一个节点挂载；NAS 支持 ReadWriteMany，多个节点上的 Pod 可以共享。
3. 新的 ext4 云盘根目录有 `lost+found`，MySQL 认为数据目录不为空，拒绝初始化。用 `subPath` 挂到子目录即可。
4. Terway 让 Pod 直接用 VPC 地址，支持 NetworkPolicy，性能更好；Flannel 用独立的 Pod 网段，不支持 NetworkPolicy，适合小规模。创建后不能更换。
5. `postgres.db` 或 `postgres.db.svc.cluster.local`。
</details>
