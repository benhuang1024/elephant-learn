# 02 类型系统进阶

> 配套代码：[structural-typing.ts](../code/lang-basics/src/structural-typing.ts)、[generics.ts](../code/lang-basics/src/generics.ts)、[narrowing-and-unions.ts](../code/lang-basics/src/narrowing-and-unions.ts)、[utility-types.ts](../code/lang-basics/src/utility-types.ts)、[branded-ids.ts](../code/lang-basics/src/branded-ids.ts)、[shared/decimal.ts](../code/packages/shared/src/decimal.ts)
> 前置：读完第 01 章，接受“类型只在编译期”。本章讲 TS 相对 PHP **真正多出来的表达力**，以及它的边界。

## 1. 结构化类型 vs 名义类型：instanceof 直觉在这里失效

PHP/Java 是**名义类型（nominal）**：`$x instanceof Order` 看类名和继承链；两个类字段完全一样，也不是同一个类型。

TS 是**结构化类型（structural）**：只看形状（成员 + 类型），形状匹配就算同一个类型，**不需要 `implements`**。

[structural-typing.ts](../code/lang-basics/src/structural-typing.ts) 的证据：

```ts
export interface MoneyLike { amount: number; currency: string; }
export interface PriceTag  { amount: number; currency: string; label: string; }  // 没有任何 implements/extends

export function total(items: readonly MoneyLike[]): number { ... }
export function moneyOf(tag: PriceTag): MoneyLike {
  return tag;   // 结构化赋值：PriceTag 形状包含 MoneyLike，允许
}
```

三个 PHP 人最需要重学的后果：

| 后果 | 说明 | 应对 |
|---|---|---|
| 可给任意库“补兼容实现” | 不需要 implements 就能满足它的接口 | 这是优点：适配器写起来极省 |
| 不相干 interface 字段一样即可互传 | `ProductId` 和 `UserId` 都是 `number` 会传错 | 加 **brand**（第 8 节） |
| 多余字段只在“字面量直接赋值”时被 excess property check 拦 | 先赋给变量再传，就不报了 | 别指望它做校验 |

函数类型也是结构化的：参数按**逆变**、返回按**协变**比较，**少写参数是允许的**（同文件 `Caster`）——对应 PHP `array_map` 传一个只吃 1 个参的闭包。

> class 也参与结构比较，但 `private`/`#` 成员会让结构比较失败，于是 class 变相成了名义类型（`Counter` 只能“自己赋给自己”）。这就是第 8 节 brand 之前、仓库自带的轻量名义化手段。

## 2. 泛型与约束：比 PHP 强，比 Java 简单

PHP 泛型只活在 PHPDoc（`@template T` / `Collection<int,User>`），运行时零信息。TS 泛型同样擦除，但**推断能力极强，多数时候不用手写实参**。

[generics.ts](../code/lang-basics/src/generics.ts) 三条主线：

```ts
export function identity<T>(value: T): T { return value; }                    // 泛型函数

// 约束用 extends，含义是「形状上必须满足」，不是「继承自」
export interface Entity<ID> { id: ID; }
export function collectIds<T extends Entity<string>>(rows: readonly T[]): string[] {
  return rows.map((row) => row.id);
}

// keyof 约束：安全取属性，编译期就校验字段名（≈ 类型版 array_pluck）
export function pluck<T, K extends keyof T>(rows: readonly T[], key: K): T[K][] {
  return rows.map((row) => row[key]);
}
```

和 Java 泛型对照，PHP 人只需替换三条直觉：

1. `T` 只是编译期变量，函数体内**拿不到 T 的运行时信息**（`erasedHint()` 演示：只能问 `typeof value`）。想分派就再传参数或用 class 构造器。
2. `extends` 是“形状匹配”，不是“继承自”——结构化类型的直接推论。
3. 没有 `? extends T` 通配符那套 PECS；默认类型参数写在 `=` 右边（`<T = never>`）。

`Collection<T>` 是泛型 class，等价于 PHP 的 `@template` + `Collection<T>`，但因为擦除，**里面不能 `new T()`**，构造器要当参数传进来（同文件注释）。

TS 5 的 `const` 类型参数把“配置对象返回精确类型”做到了 PHPDoc 做不到的程度：

```ts
export function defineConfig<const T extends Record<string, unknown>>(config: T): T { return config; }
```

`<const T>` 保留传入对象的字面量类型和 `readonly`，配合第 5 节 `satisfies` 是配置类 API 的标准姿势。

## 3. 联合与收窄：PHP 8 的 union type 只是起点

PHP 8 有 `string|int` 联合类型，但**没有编译期收窄**。TS 的价值在“收窄后每个分支都安全”。

[narrowing-and-unions.ts](../code/lang-basics/src/narrowing-and-unions.ts)：

```ts
export type Numeric = string | number;
export function stringifyLoose(value: Numeric): string {
  return typeof value === "number" ? value.toFixed(2) : value;   // typeof 收窄 ≈ is_int()/is_string()
}
```

收窄工具箱（同文件）：

| 手段 | 例子 | PHP 对应 |
|---|---|---|
| `typeof` | `typeof v === "number"` | `is_int`/`is_string` |
| `in` 运算符 | `"url" in x` 在 `{url}\|{filePath}` 里选分支 | `array_key_exists` |
| `== null` | 一次覆盖 null 和 undefined | `isset` 取反 |
| 自定义类型守卫 | `function isApiError(v): v is ApiError` | 无（要手写 is_*） |
| 断言函数 | `asserts value` 调用后收窄 | `assert()` / 提前 throw |

```ts
export function assertDefined<T>(value: T | undefined | null, what: string): asserts value {
  if (value === undefined || value === null) throw new Error(`${what} 不存在`);
}
```

> 惯用法提醒：`head()` 里 `if (items == null)` 故意用宽松 `==`——这是 JS 里“null 和 undefined 一起抓”的标准写法，文件里用 `eslint-disable` 标出例外。默认仍该 `===`。

## 4. 可辨识联合 ≈ Java sealed / PHP 手写 tag 字段

这是本章对架构师最有用的模式。**可辨识联合（discriminated union）**= 每个成员带一个字面量“标签”字段，`switch` 标签即可收窄到具体分支。

[narrowing-and-unions.ts](../code/lang-basics/src/narrowing-and-unions.ts) 的状态机：

```ts
export type OrderEvent =
  | { kind: "placed"; customer: string }
  | { kind: "paid"; amountCents: number }
  | { kind: "shipped"; trackingNo: string }
  | { kind: "cancelled"; reason: string };

export function next(state: OrderState, event: OrderEvent): OrderState {
  switch (event.kind) {
    case "placed": return "NEW";
    case "paid":   return state === "NEW" ? "PAID" : fail(state, event);
    case "shipped":return state === "PAID" ? "SHIPPED" : fail(state, event);
    case "cancelled": return state === "SHIPPED" ? fail(state, event) : "CANCELLED";
    default: {
      const exhaustive: never = event;   // 新增 kind 忘记处理 → 这行编译失败
      return exhaustive;
    }
  }
}
```

三家对照：

| | Java 21 | PHP 8 手写 | TypeScript |
|---|---|---|---|
| 表达“结果只有这几种” | `sealed interface ... permits` | 返回带 `type` 字段的数组 + `match` | 可辨识联合（`kind` 字段） |
| 穷尽检查 | switch 无 default 覆盖全部 | **无**，运行时报错 | `const x: never = event` 兜底 |
| 分支内取字段安全 | record 模式匹配 | 手动访问 | 收窄后自动 |

`never` 兜底就是 Java `sealed` 给的安全感在 TS 里的实现方式——**多一个 case、少一个处理，编译器直接拦**。这套写法在 [enum-vs-union.ts](../code/lang-basics/src/enum-vs-union.ts) 的 `TRANSITIONS` 状态表、[error-handling.ts](../code/lang-basics/src/error-handling.ts) 的 `Result<T,E>` 里反复出现。

## 5. keyof / typeof / 索引访问：类型层的“反射”

这三个运算符组合起来，能得到 PHP 只能靠文档约定的东西。见 [values-and-types.ts](../code/lang-basics/src/values-and-types.ts)、[narrowing-and-unions.ts](../code/lang-basics/src/narrowing-and-unions.ts)：

```ts
export type AnswerType = typeof answer;              // typeof 在类型位：拿一个值的类型
keyof Product                                        // "id" | "sku" | "name" | ...  取键的联合
Product["priceCents"]                                // 索引访问：number
(typeof ORDER_STATUSES)[number]                      // 数组字面量类型 → 取成员联合（见 enum-vs-union）
```

实战：`pluck<T, K extends keyof T>(rows, key: K): T[K][]`——`K extends keyof T` 限制 key 必须是 T 的字段，`T[K]` 是索引访问，返回类型精确到那一列。这是把 `array_column`/`pluck` 抬到编译期。

## 6. 映射类型 / 条件类型 / infer / 模板字面量类型

[utility-types.ts](../code/lang-basics/src/utility-types.ts) 是这四种“类型级编程”的集中演示。

**映射类型**：在 `keyof` 上遍历重建一个类型（`[K in keyof T]`）：

```ts
export type DeepReadonly<T> = {
  readonly [K in keyof T]: T[K] extends object ? DeepReadonly<T[K]> : T[K];
};
```

**条件类型**：`T extends U ? X : Y`，上面 `DeepReadonly` 里就用了它做递归。

**`infer`**：在类型里“解出”一部分，≈ 模式匹配：

```ts
export type FirstOf<T extends readonly unknown[]> =
  T extends readonly [infer H, ...unknown[]] ? H : never;
export type Unwrap<T> = T extends Promise<infer V> ? V : T;
```

**模板字面量类型**：把字符串模式变成类型（PHP 只能在运行时 `str_starts_with`）：

```ts
export type ApiPath = `/api/products/${number}` | "/api/products";
export type Route = `${Uppercase<HttpMethod>} ${ApiPath}`;   // "GET /api/products" 这种
```

映射 + 条件 + `keyof` 拼起来就是强类型事件总线（同文件 `TypedEventBus`），`EventMap` 自动变成“事件名 → 回调签名”：

```ts
export interface ShopEvents { orderPlaced: { orderId: number }; stockLow: { sku: string; stock: number }; }
export type Listener<E extends keyof ShopEvents> = (payload: ShopEvents[E]) => void;
```

> 诚实提示：`TypedEventBus.on()` 里出现了 `as never` 局部断言。泛型写入时编译器无法证明 `list` 的形状就是 `handlers[E]`——**这是类型体操触到极限的地方，见第 9 节**。

## 7. 内置工具类型逐个讲

工具类型是 TS 的“类型级 array_map”，输入类型返回类型。[utility-types.ts](../code/lang-basics/src/utility-types.ts) 顶栏的 PHP 对照记忆表 + 逐项：

| 工具类型 | 作用 | PHP 直觉 | 仓库用法 |
|---|---|---|---|
| `Partial<T>` | 全字段可选 | 更新接口入参 | `type ProductPatch = Partial<Product>` |
| `Required<T>` | 全字段必填 | — | `withDefaults(filters, Required<Filters>)` |
| `Readonly<T>` | 全字段只读（**仅第一层**） | 只读列表 | `DeepReadonly` 才递归 |
| `Pick<T, K>` | 选列 | `array_intersect_key` | `ProductListItem = Pick<Product, "id"\|"sku"\|...>` |
| `Omit<T, K>` | 删列 | `array_diff_key` | `NewProduct = Omit<Product, "id"\|"createdAt">` |
| `Record<K, V>` | 字典 | `array_fill_keys` 形状 | `Record<OrderStatus, string>` 标签表，漏 key 报错 |
| `Exclude<T, U>` | 从 union 删 | `array_diff` | 剔除状态 |
| `Extract<T, U>` | 从 union 留 | `array_intersect` | 取子集 |
| `NonNullable<T>` | 去 null/undefined | `?T` 去掉可空 | 收窄后用 |
| `Awaited<T>` | 剥 Promise 层数 | — | `Awaited<ReturnType<typeof loadProduct>>` |
| `Parameters<F>` | 取函数参数元组 | 反射 `ReflectionFunction` | 组合用 |
| `ReturnType<F>` | 取函数返回类型 | 反射 | `ProductResult = Awaited<ReturnType<...>>` |

组合示例（同文件末尾）：

```ts
export type ProductResult = Awaited<ReturnType<typeof loadProduct>>;   // Product | undefined
export type WithRelations<T, R> = T & Partial<R>;                       // 实体 + 可选关联，避免 N+1 写两遍类型
export type OrderWithItems = WithRelations<Entity<number>, { items: ProductListItem[] }>;
```

`Parameters`/`ReturnType`/`Awaited` 是“反射函数签名”，但记住第 1 章：**全在编译期**，运行时什么都没有。

## 8. branded type：给结构化类型补上“名义”这一半

第 1 节说“`ProductId` 和 `UserId` 都是 number 会传错”，brand 就是解药。

[branded-ids.ts](../code/lang-basics/src/branded-ids.ts)：

```ts
declare const BRAND: unique symbol;
export type Branded<T, B extends string> = T & { readonly [BRAND]: B };
export type ProductId = Branded<number, "ProductId">;
export type OrderId   = Branded<number, "OrderId">;
```

原理：给类型交叉一个**带 `unique symbol` 的假字段**，任何人构造不出这个形状，只能走你暴露的工厂函数——从而把结构化“伪装”成名义：

```ts
export function toProductId(raw: number | string): ProductId | null {   // 唯一入口：解析+校验
  const value = typeof raw === "string" ? Number(raw) : raw;
  return Number.isInteger(value) && value > 0 ? (value as ProductId) : null;
}
```

有了 brand，`stockOf(ProductId, ...)` 和 `ownerOf(OrderId, ...)` 就再也传不反（同文件两个函数故意长得极像，专门用来演示 brand 挡错）。

**实战版：`DecimalAmount`。** [packages/shared/src/decimal.ts](../code/packages/shared/src/decimal.ts) 用同一个手法把“金额”做成品牌字符串——因为 JS `number` 是 double，`JSON.stringify(599.00) === "599"` 根本存不住小数位：

```ts
declare const DECIMAL_BRAND: unique symbol;
export type DecimalAmount = string & { readonly [DECIMAL_BRAND]: "DecimalAmount" };
// 只有 parseDecimal / centsToDecimal 能造出来，运算全走整数分
```

[product.ts](../code/packages/shared/src/product.ts) 里 `ProductRecord.price: DecimalAmount`，编译器从此禁止你把普通 `string` 或裸 `number` 当金额传。

> brand 的代价（branded-ids.ts 顶栏明说）：**运行时不存在**，`ProductId` 还是裸 number、`DecimalAmount` 还是裸 string。序列化/反序列化时 brand 帮不了你，**入站仍要 Zod 校验**（`DecimalInputSchema`），这正是第 9 节的收尾。

## 9. `satisfies`：校验形状但不拓宽类型

`as` 是“骗编译器”，`:` 注解会把字面量拓宽（`const x: Record<string, ...>` 丢具体 key）。`satisfies` 两者都不——**只检查“满足这个形状”，但保留推断出的精确类型**。

[narrowing-and-unions.ts](../code/lang-basics/src/narrowing-and-unions.ts) 与 [enum-vs-union.ts](../code/lang-basics/src/enum-vs-union.ts)：

```ts
export const stockRules = {
  low: { min: 0, max: 10 },
  normal: { min: 11, max: 1000 },
} satisfies Record<string, { min: number; max: number }>;   // 校验每个值形状，但 stockRules 仍是具体对象

const TRANSITIONS = {
  pending: ["paid", "cancelled"],
  paid: ["shipped", "refunded"],
  /* ... */
} satisfies Record<OrderStatus, readonly OrderStatus[]>;     // 漏一个 OrderStatus 当 key → 立刻报错
```

`satisfies` 保留字面量类型的好处和代价同时体现在 `canTransition` 上：因为每个键的类型是**具体字面量数组**（不是 `readonly OrderStatus[]`），`.includes(to)` 会拒绝宽值，得 `(TRANSITIONS[from] as readonly OrderStatus[]).includes(to)` 显式放宽。这就是“保留精确性”的双刃剑。

## 10. 类型体操的边界：什么时候该停下来用运行时校验

本章给了你映射类型、条件类型、`infer`、brand、可辨识联合——表达力确实远超 PHP。但架构师的价值是**知道在哪停**。三条硬线：

1. **类型擦除划死上限**：再精巧的类型，运行时都不存在。`as`/brand/`satisfies` 都拦不住脏 JSON。凡是**边界**（HTTP body、数据库行、环境变量、第三方回调），类型一律视为不可信，用 **Zod 在运行时校验**——[shared/index.ts](../code/packages/shared/src/index.ts) 顶栏那句“**类型不是契约，schema 才是**”是全仓总纲。
2. **出现连续 `as never` / 深层 `as any` 就是信号**：`TypedEventBus.on()` 里那个 `as never`（第 6 节）说明编译器已经证不了。偶尔局部断言可接受，但当一段逻辑要靠一串断言才能过编译，说明这个抽象在跟类型系统打架——**换成运行时判别或更简单的类型**。
3. **可读性优先于万能**：条件类型套三元、递归深度 > 2 层的类型，同事（和半年后的你）读不动。PHP 里你不会为省一个 DTO 类把 array shape 写成 PHPDoc 天书，TS 同理：**能用 `interface` + 明确字段就别上 `Pick<Pick<...>>`**。

决策口诀：

| 场景 | 用类型系统 | 用运行时校验（Zod） |
|---|---|---|
| IDE 补全 / 重构安全 | ✅ | |
| 传错 id 类型 | ✅ brand | |
| “结果只有这几种” | ✅ 可辨识联合 | |
| 外部 JSON / 表单入参 | | ✅ schema + `z.infer` |
| 金额/日期格式合法性 | brand 只挡类型 | ✅ 校验值 |

第 05 章（Zod）会把这些“边界”真正落地：`z.infer` 让 schema 同时是**运行时校验器**和**类型来源**，brand 只在它信任内部之后才接管。
