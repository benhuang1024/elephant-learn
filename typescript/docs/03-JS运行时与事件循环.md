# 03 JS 运行时与事件循环 —— PHP 架构师最需要「换脑子」的一章

> 配套代码：[async-event-loop.ts](../code/lang-basics/src/async-event-loop.ts)、[error-handling.ts](../code/lang-basics/src/error-handling.ts)、[money.ts](../code/lang-basics/src/money.ts)、[null-safety.ts](../code/lang-basics/src/null-safety.ts)、[values-and-types.ts](../code/lang-basics/src/values-and-types.ts)、[shared/src/decimal.ts](../code/packages/shared/src/decimal.ts)、[shared/src/time.ts](../code/packages/shared/src/time.ts)；测试：[async-event-loop.test.ts](../code/lang-basics/test/async-event-loop.test.ts)、[money.test.ts](../code/lang-basics/test/money.test.ts)。跑一遍：`pnpm --filter @ts/lang-basics test`（80 个用例 / 12 个文件，全绿）。

## 1. 两种运行模型

```
PHP-FPM（share-nothing）                     Node（单线程常驻进程 + 事件循环）
─────────────────────────                    ─────────────────────────────────
nginx                                          (nginx / 网关)
  │                                              │
php-fpm master                                 一个 Node 进程（启动一次，运行数天）
  ├─ worker 进程 1 ── 请求 A                      ├─ 主线程：一个事件循环
  ├─ worker 进程 2 ── 请求 B                      │    同步代码 → 微任务队列 → 宏任务队列
  └─ worker 进程 3 ── 请求 C                      ├─ libuv 线程池（默认 4 个）：DNS / fs / crypto
                                                └─ 堆内存：所有请求共享同一份模块实例
每个请求：
  bootstrap 框架 → 处理 → 释放全部内存          并发 = await 让出，不是多线程
```

| 维度 | PHP-FPM | Node |
|---|---|---|
| 生命周期 | 每请求重新启动框架 | 进程启动一次，之后常驻 |
| 并发单位 | worker 进程（`pm.max_children`） | **一个线程** + 事件循环 + Promise |
| 请求隔离 | 天然隔离，变量随请求消失 | **模块级变量跨请求长期存在** |
| 内存 | 请求结束全部释放，泄漏无所谓 | 一直存活，**泄漏会累积到 OOM** |
| 阻塞 | 只阻塞这一个 worker | **阻塞整个进程的所有请求** |
| 连接 | 每请求建连（或 pconnect） | 连接池常驻复用 |
| 进程内缓存 | 只能 APCu / OPcache | 直接放堆里（也就是「全局变量」） |
| CPU 密集 | 交给多 worker | 必须 `worker_threads` / 独立服务 |
| 异常 | 请求崩了只影响该请求，php-fpm 自动重启 worker | 未捕获异常直接**杀掉整个进程** |
| 类型擦除后的值语义 | `==`/`===`、`null`、`float` | 见第 7、8 节，坑位不同 |

用过的 **Octane / Swoole / RoadRunner**，你已经有直觉了：Octane 文档里「不要在单例里保存请求状态」这句警告，在 Node 里是日常。下面六个后果，每一个都能在配套代码里跑出实测结果。

## 2. 后果一：模块级变量 = 全局共享状态

PHP 里 `static $cache` 的寿命是「一个请求」；Node 里 `let cache` 写在模块顶层，寿命是「一个进程」，而且**所有并发请求共享同一份**。

[async-event-loop.ts](../code/lang-basics/src/async-event-loop.ts) 里这段是本章最重要的 8 行：

```ts
let sharedBalance = 100;

export async function withdraw(amount: number): Promise<number> {
  if (amount > sharedBalance) throw new Error("余额不足");
  await Promise.resolve(); // 这里让出控制权，另一个调用可能已经改了 sharedBalance
  sharedBalance -= amount;
  return sharedBalance;
}
```

测试 [async-event-loop.test.ts](../code/lang-basics/test/async-event-loop.test.ts) 的断言：

```ts
resetBalance(100);
const both = await Promise.all([withdraw(60), withdraw(60)]);
expect(both).toEqual([40, -20]);   // 两个请求都通过了检查，余额变成负数
```

**没有任何线程竞争**（全程单线程），但余额仍然扣成了 `-20`。原因：

- 单线程保证的是「一段同步代码不会被打断」，**不保证**「你的函数从头到尾原子」。
- 每个 `await` 都是一个让出点；让出期间，另一个请求的代码可以任意交错。
- 这就是经典的 *check-after-await*：检查和使用之间隔着一次让出。

对照 PHP：等价于 Octane 下把「本次请求的用户 / 余额」挂在单例属性上。三条纪律：

| 该做的 | 不该做的 |
|---|---|
| 请求态只放在函数参数与局部变量 | 用模块顶层 `let` 存 userId / balance / 语言 |
| 全局可变状态显式命名 + 只读（`Map` 缓存要设上限和过期） | 「先 `if` 检查再 `await` 扣减」当业务真相 |
| 余额/库存的唯一真相放数据库（事务 + 乐观锁，见 shop-api） | 用 JS 变量做「分布式一致性」 |

## 3. 后果二：CPU 阻塞会卡死所有请求

PHP 里一个请求跑了 3 秒，只占用它自己那个 worker；Node 里一个同步 for 循环跑 3 秒，**这 3 秒内整个进程一个请求都处理不了**，健康检查也会超时。

| 任务类型 | Node 的做法 | 对应 PHP 概念 |
|---|---|---|
| IO 等待（DB / HTTP / 文件） | `await`，事件循环天然并发 | `curl_multi` / 异步队列 |
| CPU 密集（大图处理、Excel 导出、复杂计算） | `worker_threads`，或扔进队列交给独立 worker 进程 | Laravel queue worker / 独立服务 |
| 短但高频的计算 | 优化算法，别在请求路径里做 | 同 |

`pm.max_children` 是「进程数 × 单请求耗时」算吞吐；Node 是「1 个线程的可用时间片」。部署 8 核机器时，Node 要靠多进程（cluster / PM2 `instance_num` / K8s 多副本）才能吃满 CPU —— 这才是与 `pm.max_children` 对应的那个旋钮，见 [shop-api/src/main.ts](../code/shop-api/src/main.ts) 顶部注释的生产清单。

## 4. 后果三：执行顺序 —— 微任务永远插队在宏任务前面

`traceOrder()` 是一段纯同步代码，实测顺序（测试里逐条断言）：

```
同步阶段：sync:start → sync:end
微任务：  microtask:queue → microtask:then1 → microtask:then2a → microtask:then2b
宏任务：  macrotask:timeout0
```

对应代码 [async-event-loop.ts](../code/lang-basics/src/async-event-loop.ts)：

```ts
log.push("sync:start");
queueMicrotask(() => log.push("microtask:queue"));
setTimeout(() => log.push("macrotask:timeout0"), 0);
Promise.resolve().then(() => log.push("microtask:then1"));
```

| 概念 | 规则 | PHP 里有没有 |
|---|---|---|
| 同步代码 | 一个 tick 内跑完，中途不会被别的请求打断 | 有（单请求内） |
| 微任务 microtask | `Promise.then` / `queueMicrotask` / `await` 之后的部分；**当前同步代码全部结束后，按队列顺序清空所有微任务** | 无 |
| 宏任务 macrotask | `setTimeout` / `setInterval` / I/O 回调；**每执行一个宏任务之前，先把微任务队列清空** | 无（Swoole 的 `defer` 近似） |

三条容易记错的实测结论：

1. `setTimeout(fn, 0)` **不是**「立刻」，它排在所有微任务后面，哪怕延迟写 0。
2. `Promise.resolve().then()` 比 `queueMicrotask` 晚，是因为 `queueMicrotask` 先注册（谁先入队谁先出）。
3. `async` 函数里 `await` 之后的代码，本质就是一个微任务 —— 所以 `await` **不释放线程**，只释放「这段代码往后」的执行权。

推论：`asyncThrow()` 里的 `throw` 不会同步抛出，而是变成 rejected Promise：

```ts
await expect(asyncThrow()).rejects.toThrow(/只能用 await/);
```

PHP 的 `try { f() } catch` 对 `async` 函数不管用，必须 `await` 或 `.catch()`。

顺带一个性能对照（同一文件，测试实测）：`fetchSequential([20,20])` 花 ≥35ms，`fetchParallel([20,20])` 只要约 20ms。串行 `await` 循环 = PHP 里串行 curl；`Promise.all` = `curl_multi`。

## 5. 后果四：并发控制要自己写

PHP 有 php-fpm 帮你限流（`pm.max_children`）、Guzzle pool 帮你限并发。Node 里 `Promise.all(1000 个)` 会**瞬间**把 1000 个请求同时打向下游连接池，把它压垮。仓库里的解法：

```ts
export async function mapWithLimit<T, R>(
  items: readonly T[],
  limit: number,
  worker: (item: T, index: number) => Promise<R>,
): Promise<R[]> {
  const results: R[] = [];
  let cursor = 0;
  const size = Math.max(1, Math.min(limit, items.length));
  const runners = Array.from({ length: size }, async () => {
    while (true) {
      const index = cursor++;
      if (index >= items.length) return;
      results[index] = await worker(items[index]!, index);
    }
  });
  await Promise.all(runners);
  return results;
}
```

本质是「N 个消费者 + 一个共享游标」，与 fpm worker 抢任务同构。测试断言两件事：结果**保序**（`[10,20,30,40,50,60]`）且**峰值并发 ≤ 2**。

| 需求 | 用什么 | PHP 里的近似 |
|---|---|---|
| 全并发，一个失败就全崩 | `Promise.all` | `curl_multi` + 遇错中断 |
| 全并发，要每个的成功/失败 | `Promise.allSettled` | Guzzle `Pool` + `settle()` |
| 第一个出结果（含失败） | `Promise.race` | 无 |
| 第一个**成功** | `Promise.any` | 无 |
| 限流 | `mapWithLimit` / `p-limit` | `curl_multi_exec` 的 handle 上限、fpm 子进程数 |
| 取消 | `AbortSignal`（见 `waitAborted`） | 无语言级取消，只能靠超时 |

`AbortSignal` 那段代码还演示了**常驻进程必做的收尾**：`signal?.addEventListener("abort", onAbort, { once: true })` 配 `removeEventListener` —— 注册不注销就是内存泄漏（第 9 节）。

## 6. 后果五：错误处理没有安全网

| 维度 | PHP | TS / JS |
|---|---|---|
| 能 throw 什么 | `Throwable`（对象） | **任何东西**：字符串、数字、`null`、对象 |
| catch 参数类型 | `\Exception` / `\TypeError`，可选类型 | 只有 `unknown`（TS 4.4+ 默认） |
| 受检异常 | 无 | 无 |
| 异常与 async | 同步栈，能直接抓 | `async` 里的 throw 变成 rejected |
| multi-catch | `catch (A \| B $e)` | 没有，靠 `instanceof` 收窄 |
| 异常链 | `new Exception($m, 0, $previous)` | ES2022 `new Error(msg, { cause })` |

所以 [error-handling.ts](../code/lang-basics/src/error-handling.ts) 的三条纪律：

**一、只 throw `Error` 及其子类**，带 `name` / `message` / `stack` / `cause`：

```ts
export class AppError extends Error {
  constructor(message: string, readonly status: number, readonly type: string, ...) { ... }
}
export class InsufficientStockException extends ConflictException { ... }
```

层级与 Java 版 `NotFoundException` / `ConflictException` / `InsufficientStockException` 一一对应，服务端实现在
[shop-api/src/common/domain-errors.ts](../code/shop-api/src/common/domain-errors.ts)。

**二、catch 之后必须先收窄**，否则 `e.message` 编译失败：

```ts
export function caughtMessage(value: unknown): string {
  return value instanceof Error ? value.message : String(value);
}
```

**三、可预期的失败用返回值（Result），程序 bug / 基础设施故障才 throw**：

```ts
export type Result<T, E = AppError> = { ok: true; value: T } | { ok: false; error: E };

export function reserve(stock: number, requested: number): Result<number, InsufficientStockException> {
  if (requested > stock) return err(new InsufficientStockException("SKU-3", requested, stock));
  return ok(stock - requested);
}
```

因为 TS 没有受检异常，`reserve()` 的返回类型就是唯一的「强制处理」手段 —— 调用方不解构 `ok` 分支，后面根本拿不到 value。`tryInto(fn)` 则是把 try/catch 收进一个函数，弥补「没有受检异常」的补偿措施。这一条对 PHP 人是观念转变：`ValidationException` 之类在 Laravel 里是异常，在这里更适合变成 `Result`。

## 7. 后果六：值语义和类型系统不是 PHP 那一套

### `===` 与 `typeof null === "object"`

| 表达式 | 结果 | PHP 里的直觉 |
|---|---|---|
| `undefined == null` | `true` | 类比 `isset` 的行为，但 PHP 里 null 只有一个 |
| `undefined === null` | `false` | JS 有**两个**空值 |
| `0 == ""` / `0 == false` | `true` | 与 PHP 的 `==` 一致地糟糕 |
| `"1" === 1` | `false` | 弱类型强转在这里不存在 |
| `typeof null` | `"object"` | 历史 bug，语言规范永不修 |
| `NaN === NaN` | `false` | 与 PHP 一致；用 `Number.isNaN` |
| `0.1 + 0.2 === 0.3` | `false` | 和 PHP 的 float 完全同源 |

[values-and-types.ts](../code/lang-basics/src/values-and-types.ts) 里的实测值：

```ts
// eslint-disable-next-line eqeqeq, no-constant-binary-expression -- 故意演示宽松相等：这就是这两条规则存在的原因
looseEqualsNull: undefined == null, // true（=== 才是 false）—— 本仓库 eslint 强制 eqeqeq
```

仓库在 [tools/eslint-config/index.mjs](../code/tools/eslint-config/index.mjs) 里把 `eqeqeq: ["error", "always"]` 打开，就是为了替你记住这条。

空值方面 TS 的增益来自一个开关：`strictNullChecks`（在 `strict` 里）+ `noUncheckedIndexedAccess`。[null-safety.ts](../code/lang-basics/src/null-safety.ts) 里的对照表：

| JS/TS | PHP | 注意 |
|---|---|---|
| `??` | `??` | 完全同名同义 |
| `||` | `?:` | 会吃掉 `0` 和 `""` —— 老 bug 现场 |
| `?.` | 8.0 的 `?->` | 只保证「不炸」，结果仍是 `undefined` |
| `??=` `||=` `&&=` | `??=` | 同名同义 |
| `arr.find()` → `T \| undefined` | 无 | 编译器逼你处理 |
| `arr[i]` → 加 `noUncheckedIndexedAccess` 后带 `\| undefined` | 越界 warning + null | 本仓库全仓打开了它 |

### number / BigInt 与金额

```ts
bigIntegerLiteral: 2n ** 64n,  // BigInt，参与运算前必须加 n，且不能与 number 混算
```

| 类型 | 实际是什么 | 能不能用来存钱 |
|---|---|---|
| `number` | IEEE-754 double，无 `PHP_INT_MAX` 溢出概念，超过 `Number.MAX_SAFE_INTEGER` 会静默变错 | ❌ |
| `BigInt` | 任意精度整数，但不能与 `number` 混算、没有小数、`JSON.stringify` 直接抛错 | ❌ 太重 |
| 整数分（cents） | `number` 存「分」，永远整数 | ✅ 与 PHP「金额存 int 分」一模一样 |
| 定点小数字符串 | `"599.00"` 品牌字符串，运算时转分 | ✅ 跨语言契约用这个 |

[money.ts](../code/lang-basics/src/money.ts) 的实现思路和 `brick/money` 相同，重点是让编译器帮你守值对象：构造即校验、只读字段、运算返回新实例。

```ts
if (!Number.isInteger(cents)) throw new TypeError(`金额必须是整数分，收到 ${cents}`);
export function sumMoney(items: readonly Money[]): Money {
  return items.reduce((acc, item) => acc.plus(item), Money.zero(first.currency));
}
```

测试里最有价值的一条：`sumMoney([Money.of("0.1"), Money.of("0.2")]).cents === 30` —— 浮点写法拿到的是脏值。

**然后是这个仓库和 Java 版真实对不上的一处差异**，见
[packages/shared/src/decimal.ts](../code/packages/shared/src/decimal.ts)：

> MySQL `NUMERIC(12,2)` 经 Jackson 输出 `599.00`（BigDecimal 带 scale）；JS 里
> **`JSON.stringify(599.00) === "599"`** —— 数字字面量根本没有「几位小数」的概念。

所以这个包的方案是：**DTO 层用品牌字符串 `"599.00"` 表示金额，运算全走整数分**，出口才由 HTTP 层写回 JSON 数字；前端一律用同一个包的 schema 把裸数字收回 `DecimalAmount`。于是语义等价（金额相同）、字面差异（`599` vs `599.00`）被关在两个函数里，不会泄漏到业务代码。

```ts
export type DecimalAmount = string & { readonly [DECIMAL_BRAND]: "DecimalAmount" };
export function toWireDecimal(amount: DecimalAmount): number { return Number(amount); }
```

### Date 与 Temporal

JS 的 `Date` 只有一个值：UTC 毫秒。它**永远带时区**，`toISOString()` 一定给你 `...Z`；也没有 PHP `Carbon` / Java `LocalDateTime` 那种「无时区的本地时间」类型。

[time.ts](../code/packages/shared/src/time.ts) 的做法是手工拼：

```ts
/** `YYYY-MM-DDTHH:mm:ss.SSS`（本地时间，无时区后缀、无 Z）。 */
export function localIsoDateTime(date: Date): string {
  const date_ = `${date.getFullYear()}-${pad(date.getMonth() + 1)}-${pad(date.getDate())}`;
  ...
}
```

测试断言 `expect(iso).not.toContain("Z")` —— 为的是和 Java 版 `LocalDateTime` + `ISO_LOCAL_DATE_TIME` 对齐。另外注意 `getMonth()` 返回 0-11（PHP 的 `format('m')` 是 1-12），这是最常见的 off-by-one。

Temporal（新一代日期 API）目前还没进入 Node 24 的内置对象，本仓库没有任何代码依赖它。**当前现实**：`Date` + 自己写格式化，或引 `date-fns` 这类纯函数库；展示层用原生 `Intl.DateTimeFormat`（≈ PHP 的 `IntlDateFormatter`，见 `formatForDisplay()`）。

## 8. 附带一条最贵的：内存与常驻进程

PHP 里「请求结束全释放」替你兜住了一切低级泄漏。Node 不会。三个必须盯住的点：

| 泄漏模式 | PHP 里的表现 | Node 里怎么防 |
|---|---|---|
| 模块顶层 `Map` 当缓存 | 请求级，无所谓 | 必须有上限 + 过期（LRU / `Map` 手动淘汰），否则跑一周 OOM |
| `addEventListener` / `emitter.on` 不注销 | 随请求销毁 | 成对写 `removeEventListener` / `off`；`{ once: true }`；监听器超过 10 个 Node 会打 `MaxListenersExceededWarning` |
| 闭包捕获大对象 / 全局定时器 | 无所谓 | 定时器要 `clearTimeout`；`setInterval` 是进程级 |

`waitAborted()` 就是这个模式的示范写法：`resolve` 前显式 `removeEventListener("abort", onAbort)`。

还有一个 PHP 人想不到的：`unhandledRejection`（没人 `catch` 的 rejected Promise）会让进程退出 —— 相当于「一个请求的异常把整台机器带走了」。[main.ts](../code/shop-api/src/main.ts) 的注释把它列进了生产清单，和 `enableShutdownHooks()`（优雅停机，SIGTERM 时关闭 SQLite 句柄）放在一起。

## 9. 一句话对照表

| PHP 直觉 | Node 现实 |
|---|---|
| 脚本跑完就退出 | 进程常驻，`process.version` 只在启动时打一次 |
| 静态变量是请求级 | 模块顶层变量是**进程级** |
| 阻塞只影响当前 worker | 阻塞影响**全部请求** |
| 并发靠进程数 | 并发靠 `await` + 自己限流 |
| `try/catch` 能抓 async | 抓不到，必须 `await` / `.catch()` |
| `null` 只有一个 | `null` + `undefined` |
| `float` 存钱是坏习惯 | `number` 存钱直接是 bug，用整数分或品牌字符串 |
| 内存自动回收，泄漏无所谓 | 泄漏会累积，缓存和监听器要显式管理 |

1. 因为 `await` 是让出点：两个调用都先通过了 `amount > sharedBalance` 检查，再各自扣减。修法是「await 之后再检查」+ 把唯一真相放数据库（事务 + 乐观锁），不要靠进程内变量。
2. `queueMicrotask` 与 `.then` 都是微任务，按注册顺序执行，两者都早于 `setTimeout`（宏任务）。本仓库实测：`microtask:queue → then1 → then2a → then2b → macrotask:timeout0`。
3. JS 里得到 `"599"`，BigDecimal 输出 `"599.00"`。仓库用 `DecimalAmount` 品牌字符串在 DTO 层承载 scale，出口 `toWireDecimal()` 才转成裸数字，前端用同一个 schema 收回字符串。
4. 多进程：`cluster` / PM2 `instance_num` / K8s 多副本。这就是与 `pm.max_children` 对应的并发容量旋钮；单进程只会用一个核。
